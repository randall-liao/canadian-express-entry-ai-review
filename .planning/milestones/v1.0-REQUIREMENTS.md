# Requirements: PR Review Agents — Canadian PR Application Guide

**Defined:** 2026-06-09
**Core Value:** Every answer about which documents are required and whether the user has them right is grounded in and cited from an authoritative source — the system never guesses on immigration requirements.

## v1 Requirements

Requirements for initial release. Each maps to roadmap phases.

### Foundation & Privacy

- [x] **FND-01**: User's personal data (profile, documents, outputs) lives in a single local, git-ignored area; the shareable harness contains zero PII
- [x] **FND-02**: Tooling-enforced PII/secret scanning (pre-commit hook + CI, e.g. gitleaks) is in place before any real personal data is used
- [x] **FND-03**: Agent harness is CLI-agnostic — agent specs are portable markdown and all capability is behind shell-invokable Python tools that work identically across Antigravity, OpenAI Codex, Claude, and GitHub Copilot
- [x] **FND-04**: Shared Python tooling is packaged so a non-technical applicant can run it via a simple CLI (e.g. `crawl`, `query`, `check`) without manual virtualenv setup

### Crawler & Corpus

- [x] **CRWL-01**: Re-runnable crawler ingests IRCC canada.ca PR / Express Entry guidance and document-checklist pages
- [x] **CRWL-02**: Crawler ingests the IRPA Act and IRPR regulations from the Justice Laws site
- [x] **CRWL-03**: Crawler ingests the relevant IRCC Program Delivery Instructions (PDIs)
- [x] **CRWL-04**: Crawler respects robots.txt and crawl-delay, rate-limits politely, and records attribution metadata plus a "not official" label on legislation text
- [x] **CRWL-05**: Corpus is stored as clean markdown chunks, each with metadata (source URL, title, section, crawl date, content hash)
- [x] **CRWL-06**: A lightweight local keyword index (SQLite FTS5 / BM25, no external service) is built over the corpus chunks

### Grounding & Retrieval

- [x] **GND-01**: A `search` tool returns ranked corpus chunks as JSON, each with a citation object keyed by a stable `chunk_id` (source, title, section, url, crawl_date)
- [x] **GND-02**: Every requirement statement an agent makes carries at least one citation (source + section + crawl date) back to the corpus
- [x] **GND-03**: A deterministic grounding gate verifies the agent's cited quoted span is an actual substring of the retrieved chunk (rejects decorative/hallucinated citations)
- [x] **GND-04**: When no grounded source exists, the agent abstains ("not found in corpus") rather than guessing

### Personalized Checklist (Validation Layer 1)

- [x] **CHK-01**: User maintains a private case profile (citizenship, residence history, family composition, program/stream, education claim) inside the PII area
- [x] **CHK-02**: System generates a personalized completeness checklist (required vs. still-missing documents) derived from the user's case profile
- [x] **CHK-03**: Residence history (6-month / 10-year rule) determines which police certificates are required for which people
- [x] **CHK-04**: Program/stream and job-offer status determine whether proof of funds is required or exempt

### Per-Document Check Agents (Validation Layer 2)

- [x] **DOC-01**: Language-test agent checks approved test/option (IELTS General Training, CELPIP-General, TEF/TCF Canada), <2-year validity, all four abilities, and minimum CLB — all rules cited from corpus
- [x] **DOC-02**: ECA agent checks IRCC-designated issuing organization, correct purpose, <5-year validity, and that the report covers the claimed credential — cited from corpus
- [x] **DOC-03**: Proof-of-funds agent checks the family-size minimum amount (looked up from corpus, never hardcoded), bank-letter content rules, legal accessibility, recency, and exemption logic
- [x] **DOC-04**: Police-certificate agent applies the per-country 6-month/10-year residence rule, recency rules (current vs. other countries), colour-scan-of-original format, and per-country issuance guidance
- [x] **DOC-05**: Medical-exam (IME) agent checks designated panel physician, the confirmation/upfront-results document, ~12-month validity with expiry-risk flagging, and coverage of all family members

### Translation Helper

- [x] **VAL-01**: Translation helper determines which of the user's documents require certified translation (+ translator affidavit) for non-EN/FR sources, and surfaces this as a dependency of the police-certificate, birth, marriage, and work-reference documents

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Immigration legal advice / "will I be approved?" | Unauthorized practice of law and liability; the tool surfaces and cites official rules only, and is not a substitute for a licensed RCIC/lawyer |
| Auto-submission to IRCC / logging into the user's account | Against IRCC ToS and a major security/PII risk; the system guides, the user acts |
| Pre-ITA CRS scoring / profile optimization | Different problem; the system begins after an ITA is received |
| Layer-3 content inspection (reading uploaded PDFs/scans) | Hardest layer; needs document parsing + PII-handling maturity; deferred stretch goal |
| Vector / embedding semantic index | Corpus is small (single-digit to low-tens of MB); markdown + metadata + keyword index suffices and keeps the system dependency-light and CLI-agnostic |
| Other programs (PNP, family sponsorship, study/work permits) | Different document rules; dilutes focus — structure stays generalizable but only Express-Entry-post-ITA ships |
| Storing the user's actual documents in the repo | Catastrophic PII leak into a public repo — the #1 risk to avoid |
| Hard-coding dollar amounts / validity windows in agent prompts | IRCC updates amounts and rules; stale values would be both wrong and un-grounded — always retrieve from corpus with citation + crawl date |
