# Roadmap: PR Review Agents — Canadian PR Application Guide

## Overview

This project delivers a CLI-agnostic, RAG-grounded multi-agent system that guides a post-ITA Canadian Express Entry applicant through gathering and validating their e-APR documents — where every requirement statement is grounded in and cited from an authoritative corpus (IRCC canada.ca, IRPA/IRPR, IRCC PDIs). The journey follows a strict dependency chain dictated by two non-negotiable invariants that must be established as *tooling* before any real data is touched: **no PII in the public repo** and **no ungrounded claim**. We begin by laying the safety foundation (PII boundary, secret/PII scanning, CLI-agnostic shell-tool contract), then build the citable corpus (crawler → chunker → indexer/search contract), prove the grounded per-document agent loop end-to-end with a single reference agent (police certificate) plus the deterministic grounding gate and abstention, then fan out the personalized Layer-1 checklist and the remaining mandatory document agents, and finally verify portability across all four target CLIs.

## Phase Details

### Phase 1: Foundation — PII Boundary, Secret/PII Scanning & Harness Skeleton
**Goal**: A shareable, CLI-agnostic harness skeleton exists in which all personal data is structurally confined to a git-ignored area and tooling actively blocks PII/secrets from ever being committed — established before any real data is crawled or used.
**Mode:** mvp
**Depends on**: Nothing (first phase)
**Requirements**: FND-01, FND-02, FND-04
**Success Criteria** (what must be TRUE):
  1. No file under `personal/` is ever tracked by git; a fresh clone contains zero PII and all runtime output is routed only inside `personal/`.
  2. A pre-commit hook and CI job (gitleaks + a custom Canadian-immigration PII regex) fail the build on any secret/PII hit, including a scan of git history.
  3. A non-technical user can install and invoke the packaged CLI via a single command (e.g. `uv run pr-tools --help`) without manual virtualenv setup.
  4. A `personal.example/` synthetic profile schema runs the tooling end-to-end with zero real data, and the shell-invokable Python tool contract (specs + `python -m tools.*`) is in place with thin per-CLI pointer files.

### Phase 2: Crawler — Polite Ingestion of Authoritative Sources
**Goal**: A re-runnable, robots-aware crawler ingests the full authoritative corpus (IRCC guidance, IRPA/IRPR, IRCC PDIs) into timestamped raw snapshots while recording attribution.
**Mode:** mvp
**Depends on**: Phase 1
**Requirements**: CRWL-01, CRWL-02, CRWL-03, CRWL-04
**Success Criteria** (what must be TRUE):
  1. Running the crawler fetches IRCC canada.ca PR/Express Entry guidance and document-checklist pages, IRPA + IRPR from Justice Laws, and the relevant IRCC PDIs into timestamped `raw/` snapshots.
  2. Re-running the crawler refreshes content safely and incrementally (re-runnable corpus refresh as IRCC content changes).
  3. The crawler obeys robots.txt and crawl-delay, rate-limits politely, and identifies itself with a descriptive User-Agent.
  4. Every fetched source records attribution metadata, and legislation text carries a visible "not an official version" label.
**Plans**: TBD

### Phase 3: Corpus Schema & Chunker
**Goal**: Raw snapshots become clean, citable markdown chunks each carrying immutable provenance metadata, ready for indexing.
**Mode:** mvp
**Depends on**: Phase 2
**Requirements**: CRWL-05
**Success Criteria** (what must be TRUE):
  1. The chunker converts raw HTML/PDF into clean markdown chunks under `corpus/`, with legislation chunked by section/subsection (not token windows).
  2. Every chunk carries frontmatter with a stable `chunk_id`, source URL, title, section path, crawl date, and content hash, all indexed in a `manifest.json`.
  3. Re-running the chunker on unchanged raw input produces identical `chunk_id`s (no citation breakage), while content changes are detectable via `content_sha256`.
  4. A golden-set assertion confirms the proof-of-funds table and other key values extract faithfully from source.
**Plans**: TBD

### Phase 4: Indexer & Search/Citation Contract
**Goal**: A frozen, shell-invokable search contract returns ranked corpus chunks as JSON with citation objects — the one interface every agent depends on, locked early because it is the most expensive to change.
**Mode:** mvp
**Depends on**: Phase 3
**Requirements**: CRWL-06, GND-01
**Success Criteria** (what must be TRUE):
  1. An SQLite FTS5/BM25 index builds over the corpus chunks using no external service.
  2. `python -m tools.search "<query>"` returns ranked chunks as JSON, each with a citation object keyed by a stable `chunk_id` (source, title, section, url, crawl_date).
  3. `--cite <chunk_id>` returns the exact stored chunk text, enabling downstream grounding verification.
  4. A recall test on known queries — including curated synonyms/aliases (e.g. "proof of funds" / "settlement funds" / "LICO") — returns the expected chunks.
**Plans**: TBD

### Phase 5: Grounding Gate & Reference Document Agent (Police Certificate)
**Goal**: The full grounded-agent loop (profile slice → search → cited findings) is proven end-to-end with one reference agent, enforcing machine-checked citations and abstention, before any agent fan-out.
**Mode:** mvp
**Depends on**: Phase 4 (search/citation contract), Phase 1 (PII profile schema)
**Requirements**: GND-02, GND-03, GND-04, DOC-04
**Success Criteria** (what must be TRUE):
  1. The police-certificate agent emits structured findings where every requirement statement carries at least one citation (source + section + crawl date) back to the corpus.
  2. A deterministic gate rejects any finding whose cited quoted span is not an actual substring of the retrieved chunk — a decorative/hallucinated citation fails CI.
  3. Asked a question with no grounded source, the agent abstains ("not found in corpus") rather than guessing, verified by an adversarial out-of-corpus test set.
  4. The police-certificate agent applies the per-country 6-month/10-year residence rule, recency rules, and colour-scan-of-original format, each rule cited from the corpus, with a shared per-document `_contract.md` in place.
**Plans**: TBD

### Phase 6: Case Profile & Personalized Layer-1 Checklist
**Goal**: A private case profile drives a personalized, grounded Layer-1 completeness checklist of required-vs-missing documents, including translation dependencies — Layer-1 precedes the Layer-2 rule-matching fan-out.
**Mode:** mvp
**Depends on**: Phase 5 (grounding gate), Phase 4 (search contract)
**Requirements**: CHK-01, CHK-02, CHK-03, CHK-04, VAL-01
**Success Criteria** (what must be TRUE):
  1. The user maintains a private case profile (citizenship, residence history, family composition, program/stream, education claim) inside the PII area, never tracked by git.
  2. The system generates a personalized completeness checklist of required vs still-missing documents derived from the profile, with each "required" item carrying a corpus citation.
  3. Residence history correctly determines which police certificates are required for which people, and program/stream + job-offer status correctly determine whether proof of funds is required or exempt (a CEC-exempt regression case passes).
  4. The checklist flags which of the user's documents (police certificate, birth, marriage, work-reference) require certified translation plus translator affidavit for the non-EN/FR applicant.
**Plans**: TBD

### Phase 7: Remaining Mandatory Document Agents (Layer-2 Rule-Matching)
**Goal**: Each remaining mandatory document type gets a grounded check agent following the proven contract, matching the user's documents against IRCC rules with no volatile values hardcoded.
**Mode:** mvp
**Depends on**: Phase 6 (checklist orchestration), Phase 5 (agent contract)
**Requirements**: DOC-01, DOC-02, DOC-03, DOC-05
**Success Criteria** (what must be TRUE):
  1. The language-test agent checks the approved test/option, <2-year validity, all four abilities, and minimum CLB, each rule cited from the corpus.
  2. The ECA agent checks the IRCC-designated organization, correct purpose, <5-year validity, and that the report covers the claimed credential, cited from the corpus.
  3. The proof-of-funds agent looks up the family-size minimum amount from the corpus (never hardcoded), and checks bank-letter content, legal accessibility, recency, and exemption logic.
  4. The medical (IME) agent checks the designated panel physician, the confirmation/upfront-results document, ~12-month validity with expiry-risk flagging, and coverage of all family members.
  5. A grep finds no inlined dollar amounts or validity windows in agent prompts; all volatile values resolve from the corpus via a `volatile_fields` registry with citation + crawl date.
**Plans**: TBD

### Phase 8: Multi-CLI Conformance Verification
**Goal**: The same portable specs and shell tools are proven to run identically across all four target CLIs, closing the CLI-agnostic guarantee once agent behavior is stable.
**Mode:** mvp
**Depends on**: Phase 7, Phase 5 (stable agent behavior)
**Requirements**: FND-03
**Success Criteria** (what must be TRUE):
  1. Agent specs are portable markdown and all capability is invoked through shell-invokable Python tools, with no dependency on any single CLI's proprietary tool/MCP surface.
  2. A single grounded-question conformance scenario (grounded question → verified citation) passes identically under Antigravity, OpenAI Codex, Claude, and GitHub Copilot.
  3. Switching CLIs requires changing only a thin per-CLI pointer file, with no change to the canonical specs or tools.
