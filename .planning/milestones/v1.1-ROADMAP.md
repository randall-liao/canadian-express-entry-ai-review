### v1.1 — Corpus Coverage & Completeness

> 🚧 ACTIVE — defined 2026-06-09. Continues phase numbering from v1.0 (starts at Phase 9).

**Why:** v1.0's crawler only follows links inside each seed's path prefix and is bounded by
per-source page caps, so authoritative content *outside* the subtree is silently missed —
confirmed gaps: ~72 uncrawled IRPA-related regulations/versions and ~7 referenced
Express-Entry guidance pages in sibling sections — and nothing measures the
"skeleton vs. complete" gap. v1.1 makes corpus coverage **measurable and enforced** by
*extending* the existing `tools/` pipeline (crawl → attachments → chunk → validate →
index → search), not rebuilding it. Build order: **measure** the gap (coverage auditor) →
**close** it under explicit scope guards (expanded crawl) → **detect** skeletal/JS-rendered
gaps (completeness validator) → **integrate** the refreshed corpus and wire the new gates
into CI without breaking the grounding contract.

#### Phases

- [x] **Phase 9: Coverage Auditor — Measure the Referenced-vs-Captured Gap** - Per source, diff the authoritative links referenced in captured HTML against what the corpus actually holds, and emit an actionable, classified gap report.
- [x] **Phase 10: Expanded Crawl with Scope Guards** - Follow authoritative links beyond each seed's prefix (related IRPA regulations, sibling guidance, ministerial-instruction rounds) governed by host/path allowlists and caps, staying polite and incremental.
- [x] **Phase 11: Content-Completeness Validator** - Detect skeleton-vs-full-text and JS-rendered gaps across all source types, cross-checked with crawl4ai, failing CI on substantive gaps.

#### Phase Details

### Phase 9: Coverage Auditor — Measure the Referenced-vs-Captured Gap
**Goal**: Before expanding the crawl, the system can *measure* the coverage gap — for each source it diffs the authoritative links referenced in captured raw HTML against what the corpus actually captured, and produces a classified, actionable per-source gap report.
**Mode:** mvp
**Depends on**: v1.0 corpus pipeline (raw/manifest.json, corpus/manifest.json from Phases 2–4)
**Requirements**: COV-01, COV-02, COV-03
**Success Criteria** (what must be TRUE):
  1. The auditor parses every captured raw HTML page, extracts the authoritative links it references (per source type), diffs them against the captured corpus, and reports the known gaps — e.g. the ~72 uncrawled IRPA-related regulations/versions and the ~7 referenced Express-Entry sibling guidance pages — as a per-source gap report.
  2. Each referenced link is classified as `captured`, `missing`, or `out-of-scope` (with the reason recorded), so gaps are actionable and authoritative-but-out-of-subtree links are not confused with non-authoritative noise.
  3. `pr-tools coverage` and `python -m tools.coverage` both emit the gap report as machine-readable JSON and a human-readable summary.
  4. Re-running the auditor after a corpus change reflects newly-captured pages (a previously `missing` link becomes `captured`), so the report tracks progress as the crawl expands.

### Phase 10: Expanded Crawl with Scope Guards
**Goal**: The crawler can follow authoritative links *beyond* a single seed's path prefix — closing the measured gaps — while staying authoritative and bounded via explicit host + path allowlists and per-source caps, and remaining polite and incremental like the base crawl.
**Mode:** mvp
**Depends on**: Phase 9 (gap report defines what to capture), v1.0 `tools/crawl.py` + `tools/sources.py`
**Requirements**: XCR-01, XCR-02, XCR-03, XCR-04
**Success Criteria** (what must be TRUE):
  1. The crawler follows authoritative links beyond a seed's path prefix, governed by explicit scope guards — a host allowlist + path-pattern allowlist + per-source page caps — so it stays within authoritative sources and never runs unbounded.
  2. Legislation crawling captures the regulations made under IRPA that the Act/Regulations pages reference (beyond just IRPA + IRPR full text), within the scope guards, and the coverage auditor's IRPA `missing` count drops accordingly.
  3. Guidance crawling captures the referenced Express-Entry pages now sitting in sibling sections (e.g. publications, ministerial-instruction rounds), within the scope guards, and the auditor's guidance `missing` count drops accordingly.
  4. The expanded crawl still obeys robots.txt and crawl-delay, refetches nothing unchanged (incremental), and records the same attribution metadata as the base crawl.

### Phase 11: Content-Completeness Validator
**Goal**: A content-completeness validator detects pages whose captured markdown is a thin "skeleton" relative to the page's true content — across all source types and including JS-rendered gaps — cross-checked against crawl4ai, and fails CI when a substantive page or referenced authoritative document is missing or skeletal.
**Mode:** mvp
**Depends on**: Phase 10 (expanded corpus to validate), v1.0 `tools/validate_corpus.py` + `scripts/ai_crawl.py` (crawl4ai venv)
**Requirements**: CMP-01, CMP-02, CMP-03
**Success Criteria** (what must be TRUE):
  1. The validator flags pages whose captured markdown is skeletal relative to full content, extending the existing HTML coverage-ratio check to all source types and detecting JS-rendered content gaps — a deliberately-skeletal fixture page is flagged.
  2. The validator cross-checks a sample of pages with the crawl4ai (JS-rendered) extractor and flags any page where rendered content materially exceeds the captured markdown.
  3. The completeness check exits non-zero in CI when a substantive page or a referenced authoritative document is missing or skeletal, with a clear report of exactly which pages/documents failed.
  4. Pages that are legitimately short (genuine stubs, not skeletal captures) do not trip the check, keeping false positives out of CI.
**Plans**: TBD

### Phase 12: Integration — Corpus Refresh & CI Gates
**Goal**: The expanded-crawl → chunk → index pipeline refreshes the corpus end-to-end with the grounding contract intact, and the new coverage auditor and completeness validator run as CI gates alongside the existing PII/secret and test gates.
**Mode:** mvp
**Depends on**: Phase 9 (coverage), Phase 10 (expanded crawl), Phase 11 (completeness)
**Requirements**: INT-01, INT-02
**Success Criteria** (what must be TRUE):
  1. Running the expanded crawl + chunk + index refreshes the corpus end-to-end, and all existing document agents, the Layer-1 checklist, and the conformance scenario still pass the deterministic grounding gate (no regression in the frozen search/citation contract).
  2. The coverage auditor and completeness validator are wired into CI alongside the existing PII/secret and test gates, and a substantive gap fails the build.
  3. A single documented command refreshes the corpus and runs all gates, so the corpus can be re-grounded as IRCC content changes.
