## Active Milestone

### v2.0 — Shareable Crawler

> 🚧 ACTIVE — defined 2026-06-10. Continues phase numbering from v1.1 (starts at Phase 13).

**Why:** The `crawler/` pipeline works but is hardcoded to one site and one machine: IRCC
scope lives in `config.py::EXCLUDE_URL_PATTERNS`, canada.ca chrome/footer/nav stripping is
baked into `config.py` regexes, a `immigration-refugees-citizenship`→`ircc` slug
neutralization is hardcoded in `deepcrawl._is_excluded`, the IRCC source `--label` is a
default string, and absolute venv paths (`<venv>/...`) litter the
source docstrings, README, and QC_RUNBOOK. v2.0 turns this into a generic, config-driven,
MIT-licensed CLI tool any CLI agent can shell out to and anyone can point at their own
authoritative source — **without changing the crawl/QC/completeness behavior for IRCC**.
Behavior parity for the built-in IRCC/canada.ca profile is a hard constraint. Build order:
**externalize** site logic into a profile schema/loader and migrate IRCC into a shipped
default profile (parity-verified) → **package** it (Poetry, console entry point, MIT
license, attribution) → **harden** the repo for public sharing (gitignore, PII/secret/
abs-path scrub + a repeatable publish-safe check) → **integrate** with agents (stable JSON
contract + portable skill file) → **generalize** the docs (README + QC_RUNBOOK).

#### Phases

- [x] **Phase 14: Packaging & Distribution (Poetry)** - Install as a Poetry package with pinned deps, expose a single console-entry CLI (crawl / apply-verdicts / completeness / report) runnable from any directory, and ship an MIT LICENSE with attribution/robots/ToS notes.

- [x] **Phase 17: Generalized Documentation** - Rewrite the README and QC_RUNBOOK into generic install + config-authoring + run + QC guides usable for any authoritative source, free of IRCC-specific hardcoding and absolute paths.

#### Phase Details

### Phase 13: Config-Driven Engine + Built-in IRCC Default Profile

**Goal**: Site scope, exclude patterns, chrome/footer/nav stripping rules, allowed domains, the department-slug neutralization, and the source label all move out of Python source into an external site-profile config; the engine loads the active profile by name/path and applies it; a built-in IRCC/canada.ca profile reproduces today's crawl/clean/label behavior exactly; and a copyable template lets a user target their own source.
**Mode:** mvp
**Depends on**: Existing `crawler/` pipeline (deepcrawl, config, completeness, eval_runner, apply_verdicts)
**Requirements**: GEN-01, GEN-02, GEN-04, PROF-01, PROF-02
**Success Criteria** (what must be TRUE):

  1. A user can define a complete crawl target — allowed domains, include/exclude URL patterns, chrome/footer/nav stripping rules, department-slug neutralization, and source label — in an external profile config and run a crawl against it without editing any `.py` file.
  2. No site-specific constants remain in engine source: `EXCLUDE_URL_PATTERNS`, the canada.ca chrome/footer/nav regexes in `config.py`, the `immigration-refugees-citizenship`→`ircc` neutralization in `deepcrawl._is_excluded`, and the IRCC default `--label` are all read from the active profile instead of hardcoded.
  3. The built-in IRCC/canada.ca profile reproduces current behavior — re-running the reference `medical-requirements` tree yields the same recorded / skipped-scope / skipped-dup counts and byte-identical cleaned markdown as the current hardcoded engine (parity verified).
  4. An invalid or missing profile (unknown name/path, malformed schema, missing required field) fails fast with a clear, actionable error message naming the problem.
  5. A documented example/template profile is provided that a user can copy and edit to target their own authoritative source.

**Plans**: 3 plans

- [x] 13-PLAN-1.md — Freeze pre-refactor parity baseline + profile loader/schema/fail-fast validation (GEN-02, GEN-04)
- [x] 13-PLAN-2.md — Built-in IRCC profile + byte-for-byte parity (PROF-01), pure page classifier, copyable template profile (PROF-02, GEN-01)
- [x] 13-PLAN-3.md — Refactor deepcrawl.py + config.py to consume the profile; remove all site constants from engine source (GEN-01, GEN-02)

### Phase 14: Packaging & Distribution (Poetry)

**Goal**: The crawler installs as a Poetry-managed Python package with pinned dependencies, exposes a single console-entry CLI for the whole pipeline runnable from any directory, and ships an MIT license with the attribution/robots/ToS notes a public release needs.
**Mode:** mvp
**Depends on**: Phase 13 (the config-driven engine is what gets packaged)
**Requirements**: PKG-01, PKG-02, PKG-03
**Success Criteria** (what must be TRUE):

  1. The tool installs as a Python package via Poetry (`pyproject.toml` + `poetry.lock`) with pinned dependencies, reproducibly in a clean environment.
  2. A single console entry point exposes the pipeline subcommands (crawl / apply-verdicts / completeness / report) runnable from any working directory — replacing the current `python -m crawler.*`-from-repo-root invocation.
  3. An MIT `LICENSE` file is present, and attribution / robots-compliance / source-ToS / non-commercial-use notes are documented.

**Plans**: 3 plans

- [ ] 14-PLAN-1.md — MIT LICENSE + NOTICE (attribution/robots/ToS/non-commercial) + README link (PKG-03)
- [x] 14-PLAN-2.md — Poetry pyproject.toml + lock, lean core (PyYAML) + optional crawl4ai `crawl` extra, reproducible clean-env install/build (PKG-01)
- [ ] 14-PLAN-3.md — Single `corpus-crawler` console CLI (crawl/apply-verdicts/completeness/report) with lazy crawl4ai import + graceful degradation (PKG-02)

### Phase 15: Public-Safe Repository Hardening

**Goal**: The repository is safe to publish — no absolute environment paths anywhere, personal/trial corpora and crawl outputs git-ignored, no PII/secrets/credentials in the tracked tree — and a repeatable check verifies publish-safety before each share.
**Mode:** mvp
**Depends on**: Phase 14 (the documented standard install replaces the venv abs paths), Phase 13
**Requirements**: GEN-03, SAFE-01, SAFE-02
**Success Criteria** (what must be TRUE):

  1. No hardcoded absolute environment paths (venv interpreter paths like `<venv>/...`, home directories) exist anywhere in source, docstrings, README, or QC_RUNBOOK; the tool runs via the documented standard install instead.
  2. `.gitignore` excludes personal/trial corpora and crawl outputs (e.g. `trial/`, generated corpus directories), and the tracked tree contains no PII, secrets, or credentials.
  3. A repeatable check (script or documented procedure) verifies the working tree is publish-safe — no absolute home paths, no secrets, no personal data — and is runnable before sharing.

**Plans**: 2 plans

- [x] 15-PLAN-1.md — Scrub absolute paths from the crawler tree (GEN-03) and git-ignore trial/corpus_new corpora (SAFE-01)
- [x] 15-PLAN-2.md — Build the pure-stdlib publish-safety checker + tests (SAFE-02) and run the green phase gate

### Phase 16: Agent Integration — JSON Contract + Portable Skill

**Goal**: Any CLI agent can drive the pipeline by shelling out — each command emits a stable, documented JSON contract on stdout, and a portable CLI-agnostic agent skill file shows agents how to run the pipeline via that contract.
**Mode:** mvp
**Depends on**: Phase 14 (the console CLI surface the contract and skill build on)
**Requirements**: AGENT-01, AGENT-02
**Success Criteria** (what must be TRUE):

  1. Each pipeline command can emit a stable, documented JSON object (machine-readable stats/results) on stdout that an agent can parse when shelling out, with the schema documented.
  2. A portable agent skill file (plain markdown, no proprietary per-CLI tooling) is provided that drives the full pipeline via the documented CLI + JSON contract.
  3. The skill works across the target CLIs (Antigravity/Codex/Claude/Copilot/Gemini) by invoking the tool as an ordinary shell command — it depends on no single CLI's proprietary tool/skill format.

**Plans**: 2 plans

- [x] 16-PLAN-1.md — JSON output contract: global `--json` flag on all four subcommands, versioned envelope (schema_version/ok/command/result/error), machine-readable missing-crawl4ai error, new contract tests (AGENT-01)
- [x] 16-PLAN-2.md — CONTRACT.md schema docs + portable CLI-agnostic agent skill (`crawler/AGENT_SKILL.md`) + README link + end-of-phase gate (AGENT-01, AGENT-02)

**Depends on**: Phases 13–16 (docs describe the profile config, the CLI, the JSON contract + skill, and the publish-safe check)

**Success Criteria** (what must be TRUE):

  2. The QC_RUNBOOK is generalized into a config-authoring + QC guide usable for any source, with no absolute paths and no dependence on the single hardcoded `medical-requirements` example.
