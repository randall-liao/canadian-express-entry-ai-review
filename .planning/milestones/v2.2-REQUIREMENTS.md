# Requirements: PR Review Agents — Canadian PR Application Guide

**Defined:** 2026-06-11
**Milestone:** v2.2 — Corpus Duplicate Audit & Cleanup
**Core Value:** Every answer about which documents are required and whether the user has them right is grounded in and cited from an authoritative source — the system never guesses on immigration requirements.

## v1 Requirements

Requirements for milestone v2.2. Each maps to a roadmap phase.

### Duplicate Detection

- [x] **DUP-01**: Detect exact (content-hash) duplicate documents across all 16 corpus families — not just within a single crawl run
- [x] **DUP-02**: Detect near-duplicate documents across families by shared canonical/source URL
- [x] **DUP-03**: Detect near-duplicate documents across families by high text-overlap (substantially identical content)
- [x] **DUP-04**: Group detected duplicates into clusters, where one logical document corresponds to two or more file copies

### Audit Reporting

- [x] **RPT-01**: Produce an audit report listing every duplicate cluster with each member's file path, family, and source URL
- [x] **RPT-02**: Each cluster entry in the report states the keep/delete decision and its reason (completeness / QC outcome)
- [x] **RPT-03**: The report is safe to share — it contains only corpus-relative paths and source URLs, with no PII

### Corpus Cleanup

- [x] **CLEAN-01**: Select exactly one canonical copy per cluster — the most complete (longest cleaned content; prefer a copy that passed QC)
- [x] **CLEAN-02**: Delete all non-canonical copies from the local git-ignored corpus, leaving exactly one canonical copy per cluster
- [x] **CLEAN-03**: Re-validate the corpus after deletion — update live-document counts and confirm QC/completeness integrity with no dangling references

## v2 Requirements

Deferred to a future release. Tracked but not in the current roadmap.

### Continuous Dedup

- **DUP-05**: A re-runnable `corpus-crawler` subcommand performs cross-family duplicate detection on any corpus (productize the one-time audit)
- **DUP-06**: Cross-family dedup runs automatically as part of the refresh orchestrator / CI gates

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Productizing dedup into a permanent CLI subcommand or CI gate | This milestone is a one-time audit + cleanup of the current corpus; productization is deferred (DUP-05/06) |
| Semantic / embedding-based near-duplicate detection | Out of scope per project constraints (no vector index); URL + text-overlap heuristics are sufficient for this corpus |
| Manual per-cluster keep decisions | Canonical selection is deterministic (most-complete rule); no interactive adjudication this milestone |
| Changing the in-run dedup logic of the crawler | The gap is cross-family; the existing within-run dedup is unchanged |
