#### Phase Details

### Phase 20: Cross-Family Duplicate Detection & Audit Report

**Goal**: A shareable audit report identifies every cross-family duplicate cluster across all 16 families and names the one canonical copy to keep — with zero changes to the corpus (read-only dry run).
**Depends on**: Nothing (first phase of milestone; builds on shipped v2.1 corpus)
**Requirements**: DUP-01, DUP-02, DUP-03, DUP-04, CLEAN-01, RPT-01, RPT-02, RPT-03
**Success Criteria** (what must be TRUE):

  1. Running the audit over all 16 families produces a report listing every exact (content-hash) duplicate cluster — including duplicates the within-run crawler dedup never caught — with two-or-more file copies grouped per logical document. (DUP-01, DUP-04)
  2. The report also surfaces near-duplicate clusters grouped both by shared canonical/source URL and by high text-overlap (substantially identical content). (DUP-02, DUP-03)
  3. Each cluster lists every member's corpus-relative path, family, and source URL, and names exactly one canonical copy with an explicit keep/delete decision and reason (longest cleaned content; prefer a copy that passed QC). (RPT-01, RPT-02, CLEAN-01)
  4. A PII scan over the report passes — it contains only corpus-relative paths and source URLs, confirming it is safe to share. (RPT-03)
  5. The audit makes no changes to `corpus/` — the live-document count is unchanged after running it (verifiable dry run).

**Plans**: 3 plans

- [x] 20-01-PLAN.md — Wave-0 test scaffold + `crawler/dupaudit.py` interface contract (RED suite)
- [x] 20-02-PLAN.md — Detection engine: enumerate, parse, exact/URL/overlap detectors, union-find clustering, deterministic canonical selection
- [x] 20-03-PLAN.md — Report render (MD+JSON), `--json` contract, share-safety gate, read-only proof + real-corpus validation

### Phase 21: Corpus Cleanup & Re-validation

**Goal**: The local corpus holds exactly one canonical copy per duplicate cluster, with QC/completeness integrity intact, counts updated, and deletions kept local.
**Depends on**: Phase 20 (executes the keep/delete decisions from its report)
**Requirements**: CLEAN-02, CLEAN-03
**Success Criteria** (what must be TRUE):

  1. Every non-canonical copy named in the Phase 20 report is deleted from the local git-ignored `corpus/`, leaving exactly one canonical copy per cluster. (CLEAN-02)
  2. Re-running the detector against the cleaned corpus reports zero remaining cross-family duplicate clusters. (CLEAN-02)
  3. Corpus live-document counts are updated and recorded to reflect the deletions. (CLEAN-03)
  4. The QC/completeness validators pass against the cleaned corpus with no dangling references to deleted files. (CLEAN-03)
  5. `git status` confirms the deletions stayed local — no `corpus/` content was committed.

**Plans**: 5 plans
