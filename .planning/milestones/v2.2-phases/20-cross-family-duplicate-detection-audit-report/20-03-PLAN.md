<objective>

shareable report (human markdown + JSON sidecar), gate the report through the repo's publish-safety
scanner, expose the `--json` contract, and prove the run is strictly read-only over `corpus/`.

path/family/url + keep/delete + reason), provably shareable (no PII / no absolute paths), and produced
without touching the corpus (Success Criterion 5 — this phase is a read-only dry run).

generated `reports/duplicate-audit.md` + `reports/duplicate-audit.json`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| audit output → shareable report | The report is intended to be public/git-tracked; it must carry only corpus-relative paths + public source URLs. |
| audit process → corpus/ (git-ignored) | The phase is a read-only dry run; the corpus must be byte-for-byte unchanged. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-03 | Information disclosure | report rendering + write | mitigate | Render only corpus-relative paths + frontmatter source URLs; gate the rendered report through `check_publish_safe.scan_text` and abort non-zero (json: `ok:false`) on any abs-path/secret/PII violation (RPT-03). |
| T-20-04 | Tampering (read-only integrity) | `audit`/`main` writes | mitigate | Zero writes under any family dir; reports go to `--out` (default `reports/`); TestReadOnly asserts the corpus manifest is unchanged (Success Criterion 5). |
| T-20-05 | Information disclosure | `--json` error path | mitigate | Unexpected exceptions in `--json` mode become an `INTERNAL_ERROR` envelope (no traceback/abs-path leak to stdout), per `crawler/contract.py`. |
| T-20-SC | Tampering | dependency surface | accept | No package installs this phase (stdlib + existing `pyyaml`); no supply-chain checkpoint applies. |
</threat_model>
