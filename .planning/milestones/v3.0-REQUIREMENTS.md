# Requirements: PR Review Agents — Canadian PR Application Guide

**Defined:** 2026-06-20
**Milestone:** v3.0 — Grounded Answer Layer
**Core Value:** Every answer about which documents are required and whether the user has them right is grounded in and cited from an authoritative source — the system never guesses on immigration requirements.

## v1 Requirements

Requirements for milestone v3.0. Each maps to a roadmap phase.

> **Acceptance bar (locked):** *grounding-by-construction* — every factual claim in a generated
> answer/checklist must carry a citation that resolves to a real corpus chunk; any uncited or
> unresolvable claim fails the entire output (fail-closed). This bar is what makes the system
> trustworthy enough to act on a real PR application, and the gate that enforces it doubles as the
> automated eval harness.

### Retrieval

- [ ] **RET-01**: Build a re-runnable SQLite FTS5 keyword index over the clean corpus — chunk each document and store citation metadata (corpus-relative path, source URL, title, section, crawl date) alongside each chunk so every hit is directly citable. No vectors / no embeddings.
- [x] **RET-02**: Expose a `search` CLI verb that returns ranked chunks plus a stable, resolvable citation ID per hit, emitting the existing JSON-envelope contract (`crawler/CONTRACT.md`), so any CLI-agnostic agent can shell out to it.

### Grounding Gate

- [x] **GND-01**: A citation resolver verifies every citation ID emitted in an answer resolves to a real corpus chunk; unresolvable or missing citations fail closed.
- [x] **GND-02**: Grounding-by-construction gate — every factual claim in a generated answer/checklist must carry at least one resolving citation; any uncited factual claim fails the entire output (fail-closed). This gate is the acceptance bar and doubles as the automated eval harness.

### Personalized Checklist

- [x] **CHK-01**: Generate a personalized Layer-1 document checklist for a post-ITA Express Entry PR applicant from the user's local profile, with every checklist item grounded and cited to the corpus.
- [x] **CHK-02**: All user PII (profile, documents, answers) stays in the local git-ignored area — never the repo or the corpus DB.
- [x] **CHK-03**: Portable, CLI-agnostic document agents (markdown skills) consume the `search` contract to answer document questions, emitting only cited claims (subject to GND-02).

## Future Requirements

Deferred to a future release. Tracked but not in the current roadmap.

### Validation Layer 2/3

- **VAL-01**: Layer-2 requirement matching — verify each gathered document meets IRCC rules (recency, amounts, format, translation/notarization), grounded + cited.
- **VAL-02**: Layer-3 document-content inspection — read the user's uploaded PDFs/scans to verify contents against the rules.

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Vector/embedding semantic index | Corpus is small (single-digit to low-tens of MB); FTS5 keyword + BM25 is sufficient and keeps citations exact and PII on-box. Revisit only if recall proves insufficient. |
| Layer-2 requirement matching / Layer-3 content inspection | This milestone delivers retrieval + grounding + the Layer-1 completeness checklist first; rule-matching and content inspection are deferred (VAL-01/02). |
| Programs other than post-ITA Express Entry PR | Out of initial scope; structure should not preclude later generalization. |
| Sending queries/corpus to any cloud API | Violates on-box / no-PII guarantees; retrieval stays local. |
