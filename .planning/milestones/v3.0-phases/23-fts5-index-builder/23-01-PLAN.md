    - Test (no unbounded chunk): a body containing a single paragraph of ~5,000 chars (legislation-style) yields multiple chunks, each with `len(text) <= MAX_CHUNK_CHARS` — hard-split on sentence boundaries. [RET-01 SC3 / RETRIEVAL.md §3 step 5]
    - Test (heading breadcrumb): a body with `# Act`, `## DIVISION 1`, `### Heading` and paragraphs under each yields chunks whose `section` is the running heading-stack breadcrumb joined by ' › ' (e.g. `Act › DIVISION 1 › Heading`). [RET-01 SC2]
    - Test (statutory marker capture): a chunk whose first non-heading line is `**9.4** Despite ...` carries `section` ending in ' › s.9.4' (regex `^\*\*([0-9]+(?:\.[0-9]+)?)\*\*`). [RET-01 SC2/SC3 / RETRIEVAL.md §3 step 6]
    - Test (merge floor): a section whose trailing fragment is < MIN_CHUNK_CHARS is merged into the previous chunk of the same section, so no emitted chunk (except a section's sole chunk) is shorter than MIN_CHUNK_CHARS.
    - Test (determinism): `chunk(body) == chunk(body)` for every fixture — pure, no randomness, no model calls.
  </behavior>
  <action>
    Implement `def chunk(body: str) -> list[tuple[str, str]]` in `searchindex.py` per RETRIEVAL.md §3
    (the authoritative algorithm — there is NO in-repo analog, per 23-PATTERNS.md "No Analog Found").
    The caller passes an already front-matter-stripped body (Plan 02 uses `dupaudit.body_of`); this
    function does NOT re-strip.

    Algorithm (deterministic, stdlib only):
    1. Walk lines; detect ATX headings with `profile._HEADING_RE` (= `re.compile(r"^(#{1,6})\s")`) —
       reuse that exact object so heading detection matches the crawler's own notion (RETRIEVAL.md §3
       step 2). Maintain a running heading stack keyed by level (a `#` heading replaces the level-1
       slot and truncates deeper levels); the breadcrumb is the live stack joined by ' › '.
    2. Within each heading section, pack blank-line-delimited paragraphs into chunks: accumulate
       paragraphs until adding the next would exceed `MAX_CHUNK_CHARS`, targeting ~`TARGET_CHUNK_CHARS`;
       emit, then continue (RETRIEVAL.md §3 step 3).
    3. Merge an undersized trailing chunk (< `MIN_CHUNK_CHARS`) into the previous chunk of the same
       section (step 4) — so a tiny whole doc collapses to one chunk.
    4. Hard-split any single paragraph longer than `MAX_CHUNK_CHARS` on sentence boundaries (`. ` /
       newline) as a fallback so NO chunk is unbounded (step 5) — this is what tames the ~0.5-1 MB
       IRPA/IRPR FullText docs.
    5. Statutory anchor: when a chunk's first non-heading line matches `^\*\*([0-9]+(?:\.[0-9]+)?)\*\*`,
       append ' › s.<marker>' to that chunk's `section` (step 6) so a cite can name the subsection
       even though it is not a markdown heading.
    Return `[(section, text), ...]` in document order. Keep all tunables as the module constants from
    Task 1; introduce no randomness, no time, no I/O — purity is what makes SC1 (byte-identical
    `chunk_id`s) hold.

    Add `class TestChunkBounds` and `class TestChunkSection` to `test_searchindex.py` covering the six
    behaviors above. Build the fixture bodies inline as Python strings (no tempdir needed for the pure
    chunker); assert `max(len(t) for _, t in chunk(body)) <= searchindex.MAX_CHUNK_CHARS`, the tiny
    body yields `len(chunk(body)) == 1`, breadcrumb equality, the `s.9.4` suffix, and
    `chunk(body) == chunk(body)`.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| corpus markdown file → chunker | Local, semi-trusted doc text (front-matter already parsed by Plan 02) is split into chunks here. The chunker takes a plain `str` and emits `str`s — no eval, no path deref, no I/O. |
| host SQLite ↔ FTS5 module | The probe creates/drops a throwaway vtable to feature-detect FTS5 before any real work. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-04 | Denial of Service | `chunk()` on a ~1 MB legislation paragraph | mitigate | Hard-split on sentence boundaries above `MAX_CHUNK_CHARS`; a unit test asserts `max(len(text)) <= MAX_CHUNK_CHARS` so no unbounded chunk can ship (RET-01 SC3). |
| T-23-05 | Tampering / Elevation | host SQLite lacking FTS5 → silent wrong behavior | mitigate | `_probe_fts5` feature-detects FTS5 and raises `FTS5Unavailable` with an actionable message + drops the probe table; called before any corpus read (RET-01 SC4 / RETRIEVAL.md §7 P1). |
| T-23-SC | Tampering | dependency supply chain | accept | No package installs in this plan — stdlib `sqlite3`/`re`/`hashlib` only, zero new runtime deps; RESEARCH Package Legitimacy Gate is N/A (no install tasks). |

MATCH/query-injection (RETRIEVAL.md §7 P2) is **out of scope for Phase 23** — there is no user query
input in the index builder; it is mitigated in Phase 24's `search` verb. No-PII / path-confinement
threats are owned by Plan 02 (the only plan that reads the corpus and writes the DB).
