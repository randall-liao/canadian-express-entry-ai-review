<objective>
Implement `build_index(corpus, db)` — the idempotent, diffable rebuild that turns the clean
742-doc corpus into the citable `chunks` table + external-content `chunks_fts` index. It reuses the
shipped corpus-reader primitives (`dupaudit.live_docs` / `body_of` / `_frontmatter_of`), assembles
the five citation fields per chunk, mints the stable content-coordinate `chunk_id = relpath#ordinal`,
stores a `chunk_sha` staleness fingerprint, and resyncs FTS with the single `'rebuild'` command.
This is the heart of RET-01.

Purpose: RET-01 SC1 (build over exactly the live-doc set; re-run → byte-identical `chunk_id`s),
SC2 (five citation fields, never invented; `chunk_id` = content coordinates, not rowid), and SC4
(corpus text + citation metadata only — no PII, no vectors, only the `--db` path written).
Output: `build_index` in `crawler/searchindex.py` plus TestCitationFields + TestIdempotent.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| corpus dir (read) → build_index | Untrusted-ish local markdown crosses here: front-matter YAML + body. Read only via `dupaudit.live_docs` `rglob` within the resolved root; a path is never taken from file *content*. |
| build_index → SQLite `.db` (write) | The only durable write. It must land at the caller-supplied `--db` path (default `corpus/index.db`, git-ignored) and nowhere else. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-01 | Information disclosure | citation metadata + chunk text written to the DB | mitigate | The DB stores ONLY corpus text + the five PII-free citation fields (relpath/source_url/title/section/crawl_date) + source_type/chunk_sha — authoritative-source content, no profile/PII. The builder reads only `corpus/` via `live_docs` and never touches `personal/`. A test asserts no vectors/embeddings table exists. (RET-01 SC4) |
| T-23-02 | Tampering | YAML front-matter parse of a corpus file | mitigate | `yaml.safe_load` ONLY (never `yaml.load`); non-dict result coerced to `{}` (mirrors `dupaudit.parse_doc:178-180`). Front-matter is semi-trusted local input (threat T-20-02 lineage). |
| T-23-03 | Elevation of privilege / path traversal | corpus enumeration + DB write path | mitigate | Enumeration is confined to `Path(corpus).resolve()` via `dupaudit.live_docs` (`rglob`, no content-derived paths — threat T-20-01 lineage). The write target is exactly the passed `db` path; the builder writes no file outside it and never under a git-tracked path (default is git-ignored `corpus/`). |
| T-23-08 | Tampering | citation ID stability across rebuilds | mitigate | `chunk_id = relpath#{ordinal:03d}` content coordinates + `chunk_sha`, never the integer rowid (RETRIEVAL.md §7 P8); idempotency test proves byte-identical ids on re-run, so previously emitted citations keep resolving. |
| T-23-SC | Tampering | dependency supply chain | accept | No package installs — stdlib `sqlite3`/`hashlib` + already-present `pyyaml`; zero new runtime deps. Package Legitimacy Gate N/A (no install tasks). |

MATCH/query-injection is deferred to Phase 24 (no user query in the builder). SQL is always
parameter-bound — chunk text is never interpolated into a statement.
</threat_model>
