<objective>
Wire the `index` verb into the existing `corpus-crawler` CLI and document it. `crawler/cli.py` is a
THIN dispatcher (its own docstring: "No module logic is re-implemented here"), so `_cmd_index` only
validates inputs, lazy-imports `searchindex`, fails loud on missing FTS5, and emits exactly one
CONTRACT envelope — all compute stays in `searchindex.build_index` (Plan 02). The contract change is
purely additive: a new `command` value + `result` shape, with the five envelope keys and
`schema_version "1.0"` untouched. Finally, prove the whole stack over the real 742-doc corpus behind
a `skipUnless` guard.

Purpose: RET-01 SC1 (the documented `corpus-crawler --json index ...` build command), SC4 (FTS5
fail-loud at the boundary + non-zero exit), and the additive-contract promise (RETRIEVAL.md §5;
ROADMAP SC). Output: `_cmd_index` + `p_index` in `cli.py`, additive docs in `CONTRACT.md` +
`contract.py`, and TestIndexCli + TestRealCorpus.
</objective>

    (`cli.py:134-159`). Inside the handler: `from pathlib import Path` and `from crawler import

    - `corpus = Path(args.corpus_dir)`; if `not corpus.is_dir()`: in `--json` mode
      `contract.emit(contract.envelope("index", error=(contract.INVALID_INPUT, f"not a directory:

      RETRIEVAL.md §7 P1). In non-json mode print the message to stderr and return 3.
    - On success in `--json` mode: `contract.emit(contract.envelope("index", result=result))` and
      `return 0`. In non-json mode print a one-line human summary (docs/chunks) to STDERR (never
      stdout — RETRIEVAL.md §7 P11) and return 0.

    (`cli.py:317-327`) already converts it into an `internal_error` envelope (exit 4). Do NOT re-wrap.

    `p_index.add_argument("--db", default="corpus/index.db", help="output SQLite index path (default:
    corpus/index.db)")`; `p_index.set_defaults(func=_cmd_index)`. Add `index` to the subparsers
    `metavar` string (`cli.py:257`) and to the module docstring Subcommand→module map (`cli.py:9-14`).
    Keep ALL compute out of `cli.py` (it is a thin dispatcher — `cli.py:4-7`).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI argv → _cmd_index | `corpus_dir` / `--db` are caller-supplied. The handler validates `corpus_dir` is a directory and forwards `--db` to `build_index`; no shell, no eval. |
| _cmd_index → stdout (JSON contract) | In `--json` mode stdout must be exactly one `contract.emit` line; all human text goes to stderr. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-05 | Tampering / availability | host SQLite lacking FTS5 | mitigate | `_cmd_index` catches `searchindex.FTS5Unavailable` and emits a `missing_dependency` envelope + exit 3 — loud, actionable, non-zero (RET-01 SC4 / RETRIEVAL.md §7 P1). |
| T-23-06 | Spoofing / contract integrity | `--json` stdout purity | mitigate | Only `contract.emit` writes stdout; human summaries go to stderr (RETRIEVAL.md §7 P11). TestIndexCli asserts exactly one JSON line on stdout. |
| T-23-07 | Information disclosure / backward-compat break | additive contract change | mitigate | New `index` `command` value + `result` shape only; five envelope keys, `EXIT_*`, and `SCHEMA_VERSION "1.0"` unchanged; a grep gate asserts `SCHEMA_VERSION = "1.0"` (RET-01 / RETRIEVAL.md §5). |
| T-23-03 | Elevation / path traversal | `--db` write target | mitigate | Default `--db` is git-ignored `corpus/index.db`; the builder writes only that path (Plan 02). Tests write the DB inside a tempdir and never under `corpus/`. |
| T-23-SC | Tampering | dependency supply chain | accept | No package installs — stdlib only, zero new runtime deps. Package Legitimacy Gate N/A (no install tasks). |

MATCH/query-injection stays out of Phase 23 — the `index` verb takes no query, only a corpus dir +
db path. The `search` verb and its query escaping are Phase 24 (RET-02).
