<objective>
Build the **citation resolver** primitive — `resolve(db, chunk_id)` in the existing `crawler/searchindex.py`.
Given a stable `chunk_id` it returns the EXACT stored chunk text (the quotable span the grounding gate
grounds on) plus the five citation fields; an unknown OR content-drifted id returns a clean `None`
(fail-closed), NOT an exception. This is the precise primitive the Phase-25 grounding gate (GND-01) will call,
so its return shape stays stable and PII-free. Read-only over the Phase-23 index.

Purpose: RET-02 SC2 — a citation ID resolves back to its exact chunk; an unknown / stale id fails closed.
Output: `resolve()` in `searchindex.py` + TestResolve (hit / miss / sha-drift).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → `resolve(chunk_id)` → `chunks` (read-only) | `chunk_id` is untrusted but is only ever bound as a SQL parameter to `WHERE chunk_id = ?`; it never reaches FTS5 `MATCH` and never f-strings into SQL. |
| `resolve()` → returned chunk dict | Exposes only one corpus chunk's text + PII-free citation metadata; this is the exact shape the Phase-25 grounding gate (GND-01) consumes, so it must be stable + fail-closed. |
| stored `text` ↔ stored `chunk_sha` | Integrity boundary: a row whose text no longer hashes to its fingerprint is untrustworthy → resolve refuses it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-04 | Tampering / integrity (fail-closed) | resolver of unknown / stale citation ids | mitigate | `resolve()` returns None (never raises) for an unknown id AND for a content-drifted row (`chunk_sha(text) != stored chunk_sha`). A miss/stale id is a normal fail-closed signal — exactly what the GND-01 gate needs to reject ungrounded/stale citations (RET-02 SC2 / RETRIEVAL.md §4). |
| T-24-01b | Tampering (injection) | `chunk_id` → SQL | mitigate | `chunk_id` is bound to `WHERE chunk_id = ?` as a parameter (never f-string); it is not routed through `_to_match`/`MATCH`, so the FTS injection surface does not apply to the resolver. |
| T-24-03b | Information disclosure | resolver return shape | mitigate | Returns only chunk text + the five PII-free citation fields (+ chunk_id); the internal `chunk_sha` is dropped from the payload; no `personal/` is read. |
| T-24-SC | Tampering | dependency supply chain | accept | Stdlib only (`sqlite3`, `hashlib` via the existing `chunk_sha`). No new runtime deps; Package Legitimacy Gate N/A. |

`resolve()` performs NO writes (the staleness test's `UPDATE` is test-only tampering); the index is mutated solely by the Phase-23 `index` verb, so there is no tampering surface against the DB from this phase.
</threat_model>
