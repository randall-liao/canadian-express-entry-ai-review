<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI argv → `_cmd_search` | `query`, `--cite`, `--db`, `--limit`, `--family` are caller-supplied. The handler validates `--db` is a file, forwards the rest to the (already-hardened) `search()`/`resolve()` compute; no shell, no eval. The untrusted query is escaped downstream by `_to_match` (Plan 01). |
| `_cmd_search` → stdout (JSON contract) | In `--json` mode stdout must be EXACTLY one `contract.emit` line; all human/summary text goes to stderr. |
| additive contract change | New `command` value + new `result` shapes only; existing consumers must be unaffected. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-05 | Spoofing / contract integrity | `--json` stdout purity | mitigate | Only `contract.emit` writes stdout; human summaries go to stderr (RETRIEVAL.md P11). TestSearchCli asserts exactly one JSON line on stdout and `{` never on stderr. |
| T-24-06 | Information disclosure / backward-compat break | additive contract change | mitigate | New `search` `command` value + `result` shapes only; the five envelope keys, `EXIT_*`, and `SCHEMA_VERSION "1.0"` are unchanged; a grep gate asserts `SCHEMA_VERSION = "1.0"`. CONTRACT.md documents both shapes 1:1 (RET-02 SC4). |
| T-24-02b | Denial of Service | unbounded result via CLI | mitigate | `--limit` (default 10, int) is forwarded to the parameter-bound `LIMIT ?`; an empty / all-punct query is rejected as `invalid_input` exit 2 before any MATCH runs (RET-02 SC3). |
| T-24-04b | Tampering / integrity (fail-closed) | `--cite` of unknown / stale id | mitigate | `_cmd_search` treats a `resolve()` None as `result.found=false` / `chunk:null` / exit 0 (a normal fail-closed miss, not an execution error). The Phase-25 grounding gate reads `found`/`chunk` to reject ungrounded or stale citations (RET-02 SC2). |
| T-24-08b | Tampering / availability | host SQLite lacking FTS5 | mitigate | `_cmd_search` catches `searchindex.FTS5Unavailable` from `search()` → `missing_dependency` envelope + exit 3 (the `--cite` path needs no FTS5). Loud, actionable, non-zero (RETRIEVAL.md P1). |
| T-24-03c | Information disclosure | search/cite output | mitigate | Output is corpus chunk text + PII-free citation metadata only; the index is built solely from `corpus/` (no `personal/`), so no PII can surface (RET-01 SC4). |
| T-24-SC | Tampering | dependency supply chain | accept | No package installs — stdlib only across cli.py/contract.py/tests. Zero new runtime deps; Package Legitimacy Gate N/A (no install tasks). |

The query-injection surface (untrusted query → FTS5 MATCH) is mitigated in Plan 01 (`_to_match` + parameter-bound MATCH); this plan only forwards the already-escaped path and adds no new injection surface. The DB stays read-only (the index is built only by the Phase-23 `index` verb).
</threat_model>
