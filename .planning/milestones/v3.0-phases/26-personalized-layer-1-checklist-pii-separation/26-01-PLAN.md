<objective>
Lay the PII-source foundation for the personalized Layer-1 checklist: the tracked synthetic
profile schema, the `$PR_PERSONAL_DIR` + safe-YAML profile loader, and the pure applicability
logic that decides WHICH Layer-1 document items apply to a post-ITA Express Entry applicant.

This plan establishes the PII tier split at its source (CHK-01, CHK-02): the profile is the
ONLY input that carries PII (countries, dates, names, stream). `applicable_items` turns profile
facts into a list of items, each carrying a **generic, PII-free requirement label** (destined
for gated `claims[]` in Plan 02) and a **separate basis sentence** that holds the PII reason
(destined for `basis[]`, never gated, never rendered). No corpus retrieval and no gating happen
here — this is pure, deterministic compute plus the synthetic fixture that drives every test.

Purpose: personalization = claim SELECTION (which items), never text mutation (SC2). Keeping
applicability pure and PII-isolated is what makes the rendered output PII-free by construction.
Output: `crawler/checklist.py` (loader + applicability), tracked `personal.example/profile.yaml`,
and `crawler/tests/test_checklist.py` scaffold with profile + applicability tests.
</objective>
