<objective>
Build the checklist ASSEMBLER (CHK-01): the producer that turns applicable items into gated,
cited, PII-free `claims[]` and assembles the Phase-25 answer object, then runs it THROUGH the
shipped grounding gate. This is the heart of "every requirement line is a gated, cited claims[]
entry that passes the Phase-25 gate" (SC1) and "requirement text + citation come from the corpus
and are gated; applicability lives in basis[] and is never citation-checked" (SC2).

Per item: run a SHORT corpus query (2–4 tokens — `searchindex._to_match` ANDs every token, so
long queries return zero hits), take the best GENERIC hit (NEVER a country-specific page — that
leaks residence history through the relpath), resolve it to the exact stored chunk, slice a
VERBATIM quote span from the live chunk text, and build a claim whose `text` is the generic
PII-free label from Plan 01. Assemble `{question, claims[], basis[], abstentions[], prose}` with
all profile PII confined to `basis[]`. Run `grounding.check_answer` — do NOT re-implement the gate.
Zero applicable items / zero-hit / unresolvable → explicit abstention, never a bare uncited claim.

Purpose: grounding-by-construction. The rendered output (Plan 03) is PII-free BY CONSTRUCTION
because `render_answer` emits only claims+quote+citation, never basis[]; this plan guarantees the
upstream claims carry no PII and every one resolves+verbatim-matches.
Output: `grounded_claim` + `build_answer` in crawler/checklist.py, with grounds/PII/abstention tests.
</objective>
