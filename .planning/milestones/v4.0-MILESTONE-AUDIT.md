## Cross-Phase Integration (E2E flows)

The milestone integration check (gsd-integration-checker, driven against the real CLI + real corpus)
initially found **2 BLOCKERs** at the extraction→consumer seams — the pipeline could not produce a
`SUBSTANTIATED` verdict for a qualified applicant (evidence mis-linked to the alphabetically-first
factor; extractor test_type vocabulary diverged from the registry accepted-enum). Both were the classic
"phases pass individually while the integrated system fails," masked by a structural integration test
that bypassed the real `extract` seam.

**Resolution (gap-closure plan 30-05, executed + independently confirmed):**
- Deterministic per-document factor linkage scoped to claimed factors (+ `--factor` override) — replaces
  `ORDER BY factor_id LIMIT 1`.
- Shared canonical test-type vocabulary (`crawler/testtypes.py`), pinned set-equal to the registry
  accepted-enum by an anti-drift test so P30↔P31 cannot silently diverge again.
- `date_of_birth`/passport extraction linked to `core.age` (extraction-side only; auditor/registry frozen).
- A real-seam E2E regression test (`test_full_audit_real_seam.py`) that drives the actual
  import→extract→confirm→audit path — closing the integration blind spot.

**Post-fix E2E result:** `core.language.first` = `SUBSTANTIATED`; substantiated_total non-zero; cutoff
comparison meaningful; no cross-factor evidence contamination; cards vault-only; stdout PII-light. All
six integration checks now PASS; frozen core proven untouched by git diff.
