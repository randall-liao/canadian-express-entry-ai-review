# Requirements: PR Review Agents — Canadian PR Application Guide

**Defined:** 2026-07-05
**Milestone:** v4.0 — CRS Profile ↔ Document Substantiation Auditor
**Core Value:** Every answer about which documents are required and whether the user has them right is grounded in and cited from an authoritative source — the system never guesses on immigration requirements.

## v1 Requirements

Requirements for milestone v4.0. Each maps to exactly one roadmap phase (see Traceability).

**Milestone goal:** Prove the applicant's claimed CRS score is substantiated by the documents they will actually submit — catching profile↔document mismatches before e-APR submission, every admissibility/threshold verdict grounded and cited, all PII kept in a local git-ignored vault.

### Candidate Vault

- [x] **VAULT-01**: Applicant can store their CRS factor breakdown/profile plus ITA round & cutoff in a local candidate vault that is git-ignored and can never be staged or pushed
- [x] **VAULT-02**: Applicant can import raw documents (PDF/image) into the vault as content-addressed files kept out of the repo, corpus, and public reports
- [x] **VAULT-03**: Vault keeps candidate evidence strictly separate from the authoritative corpus — candidate text never enters `corpus/` and is never citable as authority (`evidence_id` distinct from `citation_id`)
- [x] **VAULT-04**: Publish-safe / gitleaks gates are extended to cover all new vault artifacts (SQLite DB/WAL, rendered images, OCR text, logs, reports) so no PII can enter the repo

### Document Extraction

- [x] **EXTRACT-01**: System automatically extracts structured values (test scores, dates, credentials, NOC/TEER, hours, duration, issuer) from the applicant's documents, rendering pages to images and reading text
- [x] **EXTRACT-02**: All extracted values start unconfirmed (`pending`) — the sole non-grounded step — and cannot support a green verdict until confirmed
- [x] **EXTRACT-03**: Applicant can confirm, correct, or reject each extracted field, shown the raw value, normalized value, source page/crop, and the factor/claim it affects
- [x] **EXTRACT-04**: Confirmations are invalidated when the source file, parser version, profile claim, or rule-registry version changes (no stale green verdicts)
- [x] **EXTRACT-05**: A `doctor` / preflight check reports extraction dependency and scan-quality problems (scanned/rotated/password-protected/low-text) instead of failing silently

### CRS Rule Registry

- [x] **RULE-01**: A PII-free CRS rule registry encodes, per factor, the admissibility rules (accepted document/test types, validity windows, issuers, thresholds, caps) with a citation and verbatim quote grounded against the corpus
- [x] **RULE-02**: Every registry rule resolves through the existing `search` / `--cite` / grounding gate; volatile thresholds may not be hard-coded in agent prose (a static check rejects inlined volatile rules)
- [x] **RULE-03**: Registry covers the full CRS grid across all four factor groups (core human capital, spouse/common-law, skill transferability, additional points)
- [x] **RULE-04**: Deterministic CRS logic (CLB/NCLC conversion, date math, duration aggregation, spouse mode, transferability caps, cutoff comparison) is computed in tested Python against the grounded rules
- [x] **RULE-05**: A current-policy arranged-employment guard treats any non-zero job-offer additional-CRS claim as `AT-RISK`/0 unless ITA-era corpus rules prove a legacy/exception case

### Substantiation Auditor

- [x] **AUDIT-01**: For each claimed CRS factor, the auditor emits a verdict — `SUBSTANTIATED` / `GAP` / `AT-RISK` / `N/A` — with a grounded rule citation and a private evidence pointer
- [x] **AUDIT-02**: `SUBSTANTIATED` is only possible when required proof exists, evidence is confirmed, values meet the claimed threshold, and the admissibility rule is grounded/cited (fail-closed; pending/low-confidence/stale never go green)
- [x] **AUDIT-03**: The auditor is split into four context-light modules (core human capital · spouse/common-law · skill transferability · additional points), reusing the frozen `search` → grounding-gate → contract primitives with no new trust-path code
- [x] **AUDIT-04**: Applicant sees factor cards showing claimed value, confirmed extracted value, substantiated points, score delta, evidence pointer, and rule citation
- [x] **AUDIT-05**: Auditor compares the substantiated CRS total against the ITA round cutoff to surface score-impact risk — without giving legal advice
- [x] **AUDIT-06**: Public output stays PII-light (generic, corpus-cited `claims[]`); full evidence-bearing reports are written only under the vault

### Safety & Conformance

- [x] **SAFE-01**: A conformance suite proves no `pending` / unconfirmed / low-confidence / stale value can produce a `SUBSTANTIATED` verdict
- [x] **SAFE-02**: Privacy tests prove no PII reaches stdout, the repo, the corpus, or public reports (non-vault output is refused)
- [x] **SAFE-03**: Retrieve-what-you-cite tests prove each registry rule grounds the intended rule (not a historical or adjacent chunk)
- [x] **SAFE-04**: Release docs frame the output as substantiation *screening*, not legal advice

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Pre-ITA CRS scoring / profile optimization | The system begins after an ITA is received; this milestone substantiates an already-claimed score, it does not compute or optimize CRS to obtain an ITA |
| Semantic entailment / NLI of document contents | Requires a model/NLI, violating the no-vectors/no-cloud constraint; only rule-matching (recency, amounts, format, admissibility) is grounded — semantic fit stays `AT-RISK` |
| Vector/embedding index over applicant documents | Corpus retrieval is SQLite FTS5 keyword-only; applicant docs are read via extraction, never indexed as vectors |
| Cloud OCR / cloud document AI / cloud LLM / remote vision APIs | Applicant documents must never leave the machine (PII) |
| Heavy ML OCR/layout stacks (PaddleOCR/EasyOCR/docTR/large OpenCV) | Dependency-light constraint; local pypdfium2/pdfminer + optional Tesseract fallback only |
| Submitting forms to IRCC or interacting with IRCC accounts | The system guides and screens; the user acts |
| Legal advice | Surfaces and cites official sources; output is substantiation screening, not a substitute for a licensed consultant/lawyer |
