<objective>
Expose the candidate vault through additive `corpus-crawler` CLI verbs, reusing the
frozen five-key JSON envelope and the stdout=JSON / stderr=human invariant. Verbs:
`vault init`, `vault profile set|show`, `vault ita set`, `vault import`, `vault list`.
Every `--json` result is PII-light (ids, counts, statuses, private output paths as
relative vault paths) — detailed values stay in `vault.sqlite`, never on stdout.

Purpose: Give the applicant a usable, machine-readable surface to create the vault and
load their profile/ITA/documents (SC1/SC2) without ever leaking PII to stdout (locked
constraint: never repo/corpus/stdout/public reports).
Output: `vault` subparser + handlers in `crawler/cli.py`, additive CONTRACT.md docs, tests.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|

| T-29-10 | Tampering (path traversal) | `vault import PATH` dest | mitigate | Dispatch to vault.import_document whose dest is resolve_within-guarded (Plan 02); PathEscapeError -> invalid_input/exit 2. |

</threat_model>
