<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| vault filesystem → git index / repo | Vault artifacts must never become tracked/stageable. |
| candidate evidence → citation surface | Candidate evidence must never be resolvable as authority. |
| vault writes → filesystem | Writes must stay inside the candidate root. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-29-13 | Information disclosure | tracked vault artifacts (DB/WAL/image/OCR/report) | mitigate | `VAULT_ARTIFACT` publish-safe category + `.gitignore` sidecars + git-staging conformance test. |
| T-29-14 | Spoofing/Elevation | evidence_id used as authority | mitigate | is_evidence_id/is_citation_id disjointness + `searchindex.resolve(evidence_id) is None` test (VAULT-03). |

| T-29-16 | Tampering (path traversal) | write outside vault via symlink/.. | mitigate | resolve_within/PathEscapeError conformance (symlink + `..` cases). |
| T-29-SC | Tampering | package installs (this plan adds none) | accept | No new package installs in this plan; foundation gate handled in 29-01. |
</threat_model>
