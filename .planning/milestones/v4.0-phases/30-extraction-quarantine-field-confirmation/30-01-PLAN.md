<objective>
Build the private vault schema and trust logic that makes automated extraction safe:
a `user_version`→2 migration adding the extraction/confirmation tables, Pydantic
boundary models, and the two functions the entire milestone's fail-closed ethos
rests on — `is_audit_eligible()` (SC3: pending/rejected/low-quality/ambiguous/stale
values can never support a green verdict) and `is_stale()` (SC4: confirmations bound
to source-file hash, page/crop hash, parser version, profile-claim version, and
rule-registry version go stale on any change).

This is the foundation both the extraction engine (Plan 02) and the confirmation
workflow (Plan 03) write through. It is fully testable with synthetic `pending` rows
inserted directly — no extraction dependencies are needed to prove the trust logic,
which is why it lands first and in isolation.

Purpose: Quarantine extraction output behind a deterministic, tested barrier so a
silent OCR/parse misread (PITFALLS-v4.0 Pitfall 1) or a stale confirmation
(PITFALLS-v4.0 Pitfall 12) can never cross into a `SUBSTANTIATED` verdict.
Output: extended `crawler/models/vault.py`, `crawler/vault.py`, and a new
`crawler/tests/test_extraction_store.py`; existing `test_vault.py` version
assertions updated for schema v2.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| extraction output → vault store | Non-grounded, probabilistic values enter the persisted store; they must be born quarantined. |
| vault store → future auditor (Phase 32) | Only `is_audit_eligible` values may cross into verdict logic. |
| store error messages → caller | Errors must never echo raw document values (PII). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-01 | Tampering | `add_extracted_value` | mitigate | Insert path FORCES `confirmation_status='pending'`; test asserts a caller cannot persist a born-confirmed value. |
| T-30-02 | Elevation of Privilege | `is_audit_eligible` | mitigate | Single tested predicate requires status∈(confirmed,corrected) AND quality='ok' AND not stale; SC3 matrix proves pending/rejected/low_quality/ambiguous are ineligible. |
| T-30-03 | Tampering | `is_stale` / confirm binding | mitigate | Confirmations bind five keys (file sha, render sha, parser ver, profile-claim ver, registry ver); SC4 cases prove any change invalidates. |
| T-30-04 | Tampering | `_migrate` v1→v2 | mitigate | Additive `IF NOT EXISTS` DDL keyed on `PRAGMA user_version`; v1 branch preserved; test proves in-place upgrade keeps v1 rows. |
| T-30-05 | Information Disclosure | VaultError / model validation | mitigate | Reuse Phase-29 hygiene: messages name field/type only; PII-light summaries omit raw_text/normalized/bbox/paths. |
</threat_model>
