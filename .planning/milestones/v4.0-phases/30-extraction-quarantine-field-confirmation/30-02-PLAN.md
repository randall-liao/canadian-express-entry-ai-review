<objective>
Add the local-only extraction stack and build `crawler/extraction.py`: the single
non-grounded interpretation step. It renders every page to an image (pypdfium2),
reads embedded text first (pdfminer.six), normalizes images (Pillow), optionally
OCRs scans (pytesseract behind the `ocr` extra), runs deterministic per-document-type
field extractors, classifies scan quality, and writes every proposed value as
`pending` through Plan 01's store — plus rendered images and text into the
git-ignored vault only.

Purpose: Deliver EXTRACT-01 (auto-extract structured values via render+read) and the
quality-detection half of EXTRACT-05 while preserving the locked constraints: local
stack only (no cloud OCR / vectors / heavy ML), PII artifacts stay in the vault, and
everything is `pending` (EXTRACT-02). Directly counters PITFALLS-v4.0 Pitfall 1
(silent misread), Pitfall 9 (dependency friction / invisible quality failures), and
Pitfall 2 (PII leak through the new image/OCR surface).
Output: extraction stack in `pyproject.toml`/`poetry.lock`, `crawler/extraction.py`,
and `crawler/tests/test_extraction.py` with synthetic fixtures.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PyPI → build/runtime | New third-party packages enter the dependency tree (supply chain). |
| applicant document → extraction | Untrusted, possibly malformed/encrypted/huge binary is parsed and rendered. |
| extraction artifacts → filesystem | Rendered images / OCR text / raw values are PII and must land only in the git-ignored vault. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-SC | Tampering | pip/Poetry installs (pypdfium2, Pillow, pdfminer.six, pytesseract) | mitigate | Blocking-human legitimacy gate (Task 1) verifies each name/version/license on pypi.org against pre-vetted STACK-v4.0 before `poetry add`; no non-vetted package added. |
| T-30-06 | Information Disclosure | render/text/OCR writers | mitigate | All writes go through `paths.resolve_within(vault.root, "files", ...)`; test scans corpus/ and stdout for the fake values and finds none. |
| T-30-07 | Denial of Service | Pillow/pypdfium2 render of a huge/bomb image or many-page PDF | mitigate | Cap render DPI, enforce Pillow `MAX_IMAGE_PIXELS`, and page-count guard; oversize pages flagged low_quality rather than OOM. |
| T-30-08 | Spoofing (false confidence) | field extractors | mitigate | Every value persisted `pending` via Plan-01 store; quality_flag set from scan-quality; extraction never writes 'confirmed' or computes points. |
| T-30-09 | Denial of Service / Repudiation | password-protected / corrupt PDF | mitigate | Catch pdfminer/pdfium decryption/parse errors → flag password_protected/low_quality and continue (or raise MissingExtractionDependency for absent deps); never a silent skip or opaque crash. |
| T-30-SC2 | Tampering | optional OCR path | accept | pytesseract is opt-in behind the `ocr` extra + a local Tesseract binary the user installs; absence is reported (Plan 04 doctor), not auto-installed. |
</threat_model>
