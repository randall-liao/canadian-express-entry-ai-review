<objective>
Deliver the confirm-what-I-read trust checkpoint on the CLI: additive `vault extract`,
`vault fields`, and `vault confirm` verbs that let the applicant review and
confirm/correct/reject each extracted field — seeing its raw value, normalized value,
source page/crop, affected CRS factor, and profile claim — and that surface the
Plan-01 audit-eligibility gate and staleness state so nothing pending, rejected,
low-quality, or stale can look green.

Purpose: EXTRACT-03 (field-level confirm/correct/reject with full context) and the
enforcement side of EXTRACT-02/EXTRACT-04, defeating PITFALLS-v4.0 Pitfall 10
(rubber-stamp confirmation) by refusing a bulk "confirm all" and requiring per-field
decisions, and Pitfall 12 (stale confirmations) by showing and re-requiring
confirmation on staleness. All `--json` output stays PII-light per the locked
constraint; the human-visible detail (which is PII) goes to the local terminal
(stderr), never the machine envelope, corpus, or tracked files.
Output: `crawler/confirm.py`, new CLI verbs in `crawler/cli.py`, and
`crawler/tests/test_extract_confirm_cli.py`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| non-grounded extraction → human confirmation | The formal barrier between machine perception and grounded evaluation; must be per-field. |
| confirmation detail view → output channel | The view is PII-rich; only the human terminal may see it, never the --json machine envelope. |
| CLI decision → vault gate | A confirm/correct/reject must not be able to mark an ineligible value eligible. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-10 | Elevation of Privilege | `vault confirm` | mitigate | Field-level only: one `--value-id` per call, no bulk "confirm all"; `apply_decision` mutates a single value; test asserts other values untouched. |
| T-30-11 | Information Disclosure | `vault fields` / `--json` envelope | mitigate | PII-rich view printed to STDERR (human) only; `--json` result carries PII-light summaries; test scans the stdout envelope for the fake raw value and finds none. |
| T-30-12 | Tampering | staleness surfacing | mitigate | `confirm_value` re-captures binding keys; `vault fields`/`vault confirm` report `stale`/`audit_eligible` from the Plan-01 gate; SC4 test proves re-confirmation is required. |
| T-30-13 | Denial of Service / Repudiation | `vault extract` missing dep | mitigate | `MissingExtractionDependency` → `missing_dependency`/exit 3 with install hint, not an opaque crash. |
</threat_model>
