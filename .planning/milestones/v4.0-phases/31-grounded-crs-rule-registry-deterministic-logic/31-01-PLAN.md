<objective>
Build the PII-free CRS rule registry ENGINE: the typed rule-row schema plus the
loader, the grounding-validation harness (reusing the frozen `search`/`--cite`/`ground`
gate), the retrieve-what-you-cite check, the full-grid coverage engine, and the static
"no inlined volatile rule" check. This is the interface-first foundation every content
and audit plan in Phase 31 builds on: it defines the rule-row contract that the four
factor-group YAML files fill in and that the deterministic CRS logic reads from.

Purpose: RULE-01/02/03 machinery. Auditors must consume CITED rules, never write their
own CRS tables; this plan makes "a rule row is only usable if its citation resolves and
its quote passes the shipped gate" an enforceable, tested invariant BEFORE any content
exists. No new trust path — the engine calls `grounding.check_answer` and
`searchindex.search`/`resolve` verbatim.

Output: `crawler/models/crs_rules.py`, `crawler/crs_rules.py`, and corpus-less synthetic
tests that prove the whole loop works in CI (against a TemporaryDirectory index), so a
corpus-less green is a real mechanism proof, not just static structure.
</objective>

Define the PII-free CRS rule-row schema as pydantic v2 models, following the
conventions in crawler/models/vault.py (from __future__ import annotations; BaseModel;
Literal enums so out-of-vocabulary values are rejected at the boundary). Reuse the

Model the rule row per ARCHITECTURE-v4.0 Pattern 3 "Suggested rule row". Define:
`Selector` (family: str — a corpus relpath-prefix family like "guidance"/"language"/
"ministerial-instructions"/"eca"/"noc-2021"; optional require_title_contains: str;
optional marker: str — the non-volatile substring used to pick the RIGHT chunk;
optional deny_families: list[str] — source families that must NOT ground this row, e.g.
year-end reports / historical amendments, to stop historical-chunk grounding per
PITFALLS-v4.0); `Citation` (chunk_id: str constrained to the `relpath#ordinal` shape,
quote: str — the verbatim substring copied from the resolved chunk at build time);
`MachineCheck` (kind: Literal["accepted_enum","threshold","validity_window","cap",
"points_table","policy_flag"]; field: str; plus kind-appropriate payload fields such as
accepted_values, min/max, window_days/effective_from/effective_to, cap_value,
points_by_level — each value paired with a citation_index into `citations`);
`VolatilityMeta` (volatility: Literal["stable","volatile"]; source_family: str;
crawl_date: str | None; effective_from/effective_to: str | None — ISO dates for
policy-dated rules such as the arranged-employment repeal). Then `RuleRow` composing
all of the above with rule_id (dotted, e.g. "core.language.first.approved_test"),
factor_group: FactorGroup, factor_ids: list[str], check_type:
Literal["admissibility","threshold","conversion","points","cap","policy"], query: str,
selector: Selector, claim_text: str, citations: list[Citation] (min length 1),
machine_check: MachineCheck. Add a `Registry` container model (rows: list[RuleRow]) with
a validator rejecting duplicate rule_ids. Do NOT model any applicant/PII field — this
registry is public. Keep validation strict (extra="forbid") so a malformed YAML row
fails loud at load.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| corpus index → registry engine | Corpus chunk text is treated as authority; the engine must ground against the INTENDED chunk, not a historical/adjacent one |
| registry YAML (author input) → loader | Author-supplied rule rows cross into typed models; malformed/oversized input must fail loud, never persist |
| registry engine → grounding gate | The engine must call the frozen gate, not fork it; a forked check could silently accept ungrounded rules |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-01 | Spoofing | retrieve_what_you_cite chunk selection | mitigate | Selector family allow-list + non-volatile marker + deny_families reproduce the document-agent selection rule; a wrong/historical chunk cannot masquerade as the cited rule |
| T-31-02 | Tampering | pydantic loader | mitigate | Strict models (extra="forbid", Literal enums, `relpath#ordinal` citation shape, min-1 citations); malformed YAML raises at load |
| T-31-03 | Repudiation/Integrity | grounding validation | mitigate | validate_registry calls the SHIPPED grounding.check_answer verbatim; no forked substring/resolve logic (grep-asserted) |
| T-31-04 | Information disclosure | rule-row models | accept | Registry is PII-free/public by construction; models carry no applicant field and never read the vault — no PII surface exists |
| T-31-05 | Elevation (bypass) | static no-inline check | mitigate | no_inlined_volatile_rules rejects volatile thresholds outside grounded rows; comment-stripping prevents a self-invalidating header |
| T-31-SC | Tampering | pyyaml/pydantic installs | accept | No new runtime deps — pyyaml (>=6) and pydantic (>=2.13) are already pinned in pyproject.toml; nothing installed this plan |
</threat_model>
