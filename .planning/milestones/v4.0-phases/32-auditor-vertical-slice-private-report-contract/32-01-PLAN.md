<objective>
Define the typed audit CORE contract that the whole Phase 32 slice (and the Phase 33
fan-out) reuses: the four-value verdict vocabulary and the two-tier report models that
make the PII boundary a *structural* guarantee rather than a runtime hope.

Two model tiers, mirroring the shipped `crawler/models/vault.py` split:
- **PII-LIGHT public tier** — `PublicClaim`, `FactorVerdict`, `PublicAuditEnvelope`. These
  cross the `--json` stdout boundary. They carry corpus `citation_id`s, verdicts, counts,
  the run id, and the private output *path* — never an applicant value, never an `ev_`
  evidence pointer (locked constraint: `claims[]` never carry PII; `citation_id` stays
  separate from `evidence_id`). This tier is what AUDIT-06 protects.
- **PII-BEARING private tier** — `PrivateFactorCard`, `PrivateAuditReport`. These are the
  full evidence-bearing report written ONLY under the candidate vault (Plan 04). They carry
  claimed vs confirmed applicant values, `ev_` evidence pointers, the substantiated-points
  score delta, and the corpus rule citations behind each verdict.

Purpose: interface-first. Every later plan (engine, report writer, CLI) builds against these
contracts instead of re-deriving field shapes, and the citation_id/evidence_id firewall is
enforced by pydantic at construction, not by convention. Covers AUDIT-02 (the verdict
vocabulary + the SUBSTANTIATED contract shape) and AUDIT-06 (the public/private tier split).

Output: `crawler/models/audit.py` + `crawler/tests/test_audit_models.py`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public model tier → `--json` stdout | PII-light models cross to an external agent; must never carry applicant values or `ev_` pointers |
| corpus citation_id ↔ vault evidence_id | corpus authority (`relpath#ordinal`) must stay strictly separate from private `ev_` pointers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-32-01 | Information Disclosure | `PublicClaim` / `PublicAuditEnvelope` | mitigate | `extra="forbid"` + a `citation_id` `field_validator` rejecting `ev_`-shaped ids make a PII/evidence field a load-time failure; the PII-bearing tier (`PrivateAuditReport`) is the only model that may hold applicant values, and `to_public_envelope` is the single tested down-projection that strips them |
| T-32-02 | Tampering | rule/report model load | mitigate | `Literal` `Verdict` + `ConfigDict(extra="forbid")` reject an out-of-vocabulary verdict or a malformed/typo'd key loudly at construction (fail-closed), never persisting a partial |
</threat_model>
