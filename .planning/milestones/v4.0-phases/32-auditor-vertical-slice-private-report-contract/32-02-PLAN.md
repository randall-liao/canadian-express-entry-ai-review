<objective>
Add the private, evidence-bearing persistence the auditor writes its audit trail into: a
schema-v3 migration of `crawler/vault.py` introducing an `audit_runs` table (one row per
`vault audit` invocation) and a `factor_verdicts` table (one row per factor verdict), plus
the id minters and record/load helpers the report writer (Plan 04) calls.

This is the vault side of the research architecture's statement that the vault "owns …
audit runs, and verdict records" (ARCHITECTURE-v4.0 §Candidate vault). These rows are
PII-bearing (they reference `ev_` evidence pointers and store the verdict/score delta) and
therefore live ONLY inside the git-ignored `vault.sqlite` — already covered by the
publish-safe `VAULT_ARTIFACT` sidecar rules. They keep applicant `evidence_id` (`ev_`)
strictly separate from corpus `citation_id`, upholding the locked separation invariant.

Purpose: give the slice a durable, re-openable audit trail keyed by a stable `run_id`, so
the public envelope (Plan 05) can surface a run id + counts while the evidence stays behind
the vault boundary. Supports AUDIT-02 (persisting WHY a verdict is/ isn't green) and
AUDIT-06 (evidence-bearing records stay vault-only).

Output: schema-v3 migration + helpers in `crawler/vault.py` + `crawler/tests/test_audit_store.py`.
</objective>
