<objective>
Build the fail-closed verdict engine — the heart of the vertical slice — for ONE pilot
factor: **first official language** (`core.language.first`). This factor is the recommended
pilot (CONTEXT.md / SUMMARY-v4.0 §Per-Factor map): it already has a complete grounded rule
set shipped in `crawler/data/crs_rules/core.yaml` (`core.language.first.approved_test`,
`.accepted_tests`, `.validity`, `.points`, plus `core.language.conversion.*`) and crisp
CLB thresholds.

`audit_factor(vault, factor_id, db, registry, *, ita_round_id=None, spouse_mode=False)`
runs the complete loop:
1. Gather the grounded rule rows for the factor into a subset `Registry`.
2. **Grounding-by-construction gate (SC1/SC5):** feed that subset through the SHIPPED
   `crawler.crs_rules.validate_registry` (which calls `grounding.check_answer` per row).
   ANY violation — or any consumed row marked `gap` — raises `AuditGroundingError`. No
   verdict, no report. This is the "writes no partial report" invariant.
3. **Evidence quarantine (SC3):** read applicant values ONLY through
   `vault.audit_eligible_values(factor_id)` (confirmed/corrected + quality ok + not stale).
   Pending / low-quality / stale / missing values simply are not returned → they can never
   support a green verdict.
4. **Deterministic threshold math (SC2):** convert raw ability scores with
   `crs_audit.to_clb` (None ⇒ AT-RISK), check freshness with `crs_audit.within_validity`,
   check the accepted-test enum + approved-test policy from the grounded rows, and award
   points with `crs_audit.score_factor` — all reading values from the grounded rows, never a
   Python literal.
5. **Verdict:** SUBSTANTIATED only if proof-exists AND audit-eligible AND threshold-met AND
   grounded+cited; otherwise GAP (missing/below-threshold/wrong-test) or AT-RISK
   (stale/unresolved/ambiguous); N/A if the factor is not claimed.

The engine RETURNS a `PrivateAuditReport` (Plan 01 model) in memory; it does NOT write files
or persist rows — that is Plan 04's job, keeping the pure verdict logic independently
testable. Covers AUDIT-02 end to end.

Output: `crawler/auditor.py` + `crawler/tests/test_auditor.py`.
</objective>

    - Happy path: four confirmed+ok+fresh ability values that convert to a CLB meeting the

      grounded registry → verdict == "SUBSTANTIATED".
    - Pending evidence: a required ability value is `pending` (not eligible) → GAP (never

    - Low-confidence: a required ability value has `quality_flag == "low_quality"` (not
      eligible) → GAP/AT-RISK, never SUBSTANTIATED.
    - Stale: a confirmed value whose binding key changed (`is_stale` true) → not eligible →
      GAP/AT-RISK, never SUBSTANTIATED.
    - Missing proof: no eligible value for a required ability/field → GAP.
    - Below threshold: eligible values that convert to a CLB below the claimed threshold →
      GAP (recalculated downward), never SUBSTANTIATED.
    - Wrong / unaccepted test type: test_type not in the grounded accepted-enum → GAP.
    - Expired: an eligible test_date outside the grounded validity window
      (`within_validity` false) → AT-RISK.
    - Semantically unresolved: a raw score that `to_clb` maps to None → AT-RISK.
    - Not claimed: factor absent from the profile → "N/A".
    - Grounding failure (SC1/SC5): a registry whose consumed row quote is NOT a substring of
      its cited chunk (fails the gate), OR a consumed `gap:true` row → raises
      `AuditGroundingError`, and the function returns NO PrivateAuditReport.
    - Grounded GAP/AT-RISK is a RESULT, not an error: assert a GAP/AT-RISK case returns a
      valid `PrivateAuditReport` (no exception raised).
  </behavior>
  <implementation>
    Create `crawler/auditor.py`:
    - Define `class AuditGroundingError(RuntimeError)` — raised ONLY on a true grounding /
      system failure (ungrounded rule, unresolved gap row). This is the sole "error" surface;
      GAP/AT-RISK/N/A are returned verdicts, never exceptions.
    - `_consumed_rows(registry, factor_id)` — select the grounded rows this factor consumes:
      rows whose `factor_ids` include `factor_id`, PLUS the conversion rows
      (`factor_ids` include `core.language.conversion`) needed by `to_clb`.
    - `_gate_or_raise(subset_registry, db)` — call `crs_rules.validate_registry(subset, db)`;
      if `violations` is non-empty raise `AuditGroundingError` with a PII-free message
      (rule_ids + reasons only). Additionally raise if any consumed row has `row.gap` true.
      This REUSES the frozen gate — do not fork `grounding.check_answer` or re-implement a
      substring check.
    - `audit_factor(vault, factor_id, db, registry, *, ita_round_id=None,
      spouse_mode=False) -> PrivateAuditReport` — orchestrates: (a) if the factor is not in
      the profile (`load_profile_factors`) → build a `PrivateAuditReport` with one N/A
      `PrivateFactorCard` and return; (b) gate the consumed rows (`_gate_or_raise`);
      (c) pull eligible evidence via `vault.audit_eligible_values(factor_id)`; (d) resolve
      the four ability raw scores + test_type + test_date from the eligible values by
      `field_name`; (e) run the deterministic checks in `crawler.crs_audit`
      (`to_clb`, `within_validity("language", test_date, reference_date, registry)`, the
      accepted-enum lookup, `score_factor("core.language.first", clb, spouse_mode,
      registry)`), where `reference_date` is the ITA round date if present else the run date;
      (f) apply the decision table below to pick the verdict + a PII-free `reason_code`;
      (g) assemble a `PrivateFactorCard` (claimed vs confirmed values, substantiated_points,
      score_delta, `evidence_ids` from the eligible values' documents, `rule_citation_ids`
      from the consumed rows' citations) and return a `PrivateAuditReport`.
      Decision table: SUBSTANTIATED iff proof-exists AND every required value is
      audit-eligible AND every ability's CLB meets the claimed threshold AND the test type is
      accepted AND the test_date is in-window AND the gate passed. Missing/unaccepted/
      below-threshold → GAP. Stale/expired/unresolved(to_clb None)/ambiguous → AT-RISK.
      Not claimed → N/A.
    - Carry NO inlined volatile threshold: every band, window, accepted value, and point
      figure is read from the grounded rows via the `crs_audit` helpers (a self-scan test may
      reuse `crs_rules.no_inlined_volatile_rules([__file__])`).
    Prefer small, pure helpers so the matrix tests can target each branch. Keep every error
    message PII-free (field names / rule ids / reason codes only).
  </implementation>
