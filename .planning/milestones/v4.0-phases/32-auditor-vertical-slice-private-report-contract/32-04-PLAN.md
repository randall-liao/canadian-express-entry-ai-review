<objective>
Turn an in-memory verdict into durable, vault-ONLY output — fail-closed. `run_audit` is the
orchestration seam between the pure engine (Plan 03) and the CLI (Plan 05):

1. Call `crawler.auditor.audit_factor(...)`.
2. **If it raises `AuditGroundingError`:** write NOTHING — no report file, no `audit_runs`
   row, no `factor_verdicts` row — and re-raise (SC5: "a grounding failure writes no partial
   report"). Because nothing is written until after a verdict is computed, the vault can
   never hold a half-finished report.
3. **On a valid verdict (SUBSTANTIATED / GAP / AT-RISK / N/A):** write the full
   evidence-bearing `PrivateAuditReport` as JSON **and** a human-readable factor-card
   Markdown, ONLY under `personal/candidates/<id>/output/crs-audit/<run_id>.{json,md}`
   (resolved through `crawler.paths.resolve_within`, which rejects `..`/symlink escapes);
   persist the `audit_runs` + `factor_verdicts` rows (Plan 02 helpers); and down-project the
   report to a `PublicAuditEnvelope` (Plan 01 `to_public_envelope`) carrying the
   vault-RELATIVE report path. Return `(PrivateAuditReport, PublicAuditEnvelope)`.

The report file path subtree `output/crs-audit/` and the `.json`/`.md` extensions are
ALREADY inside the shipped publish-safe `VAULT_SUBTREES` / `VAULT_ARTIFACT_EXTS` allowlist —
so the report artifact type is covered the moment it is written under that subtree (Plan 05
adds the regression assertion). Covers AUDIT-02 (durable audit trail of the verdict) and
AUDIT-06 (full report is vault-only).

Output: `crawler/audit_report.py` + `crawler/tests/test_audit_report.py`.
</objective>
