<objective>
Close the single scoped BLOCKER that fails SC3 (AUDIT-04) and SC4 (AUDIT-05) for spouse-mode candidates: `crawler/crs_audit.py::score_factor` filters candidate rows with `(row.factor_group == "spouse_common_law") != spouse_mode`, which EXCLUDES the `core_human_capital` language points row whenever `spouse_mode=True`. For a CORE language factor the grounded with-spouse and without-spouse points live as LABELLED `PointsEntry` rows (`clb9_with_spouse=29` / `clb9_without_spouse=31`) INSIDE the one core row (verified in `crawler/data/crs_rules/core.yaml`), NOT in a separate `spouse_common_law` group. The current filter therefore returns `None` for `core.language.first` / `.second` in spouse mode, so those cards reach SUBSTANTIATED with blank `substantiated_points` / `score_delta` (SC3) and contribute 0 to the substantiated total (SC4 undercount of ~116+ points).

The fix makes `score_factor`, for core-group factors, INCLUDE the owning core row in BOTH modes and select the mode-specific grounded entry by LABEL — mirroring the already-correct `crawler/auditors/core.py::_grounded_points` / `_age_points` (which score age/education correctly in both modes). `spouse_common_law` rows (the SPOUSE'S OWN factors) stay gated to spouse mode, and the transferability `factor_ids[0]` ownership guard + cap clamp are preserved.

This is a gap-closure plan. It touches ONLY the scoring defect: it does NOT re-plan the phase and MUST NOT regress SC1, SC2, SC5, the transferability ownership fix (no CLB-9 tier leak), arranged-employment AT-RISK/0, no-spouse-mode language = 124, the frozen trust path, or Phases 29–32.

Purpose: restore AUDIT-04 (all six card fields populated for spouse-mode language) and AUDIT-05 (correct substantiated total in spouse mode).
Output: mode-aware `score_factor`, a unit regression suite, and an end-to-end spouse-mode points assertion.
