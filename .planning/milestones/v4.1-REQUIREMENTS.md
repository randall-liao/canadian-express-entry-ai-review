# Requirements: PR Review Agents — Canadian PR Application Guide

**Defined:** 2026-07-17
**Milestone:** v4.1 — CRS Auditor Hardening & Remediation
**Core Value:** Every answer about which documents are required and whether the user has them right is grounded in and cited from an authoritative source — the system never guesses on immigration requirements.

## v1 Requirements

Requirements for milestone v4.1. Each maps to exactly one roadmap phase (see Traceability).

**Milestone goal:** Close the v4.0 auditor's known fail-closed coverage and operational gaps, then turn every actionable finding into a grounded private remediation checklist and an explicitly redacted professional-review packet.

**Execution directive:** Planning and execution are autonomous. Agents make reasonable scope and implementation decisions, record rationale in milestone artifacts, and do not interrupt the operator with clarification questions.

### Coverage Completion

- [x] **COV-01**: Applicant receives grounded first-official-language points for every benchmark level emitted by the supported test-conversion tables, including higher-CLB results, without fabricated or silently missing points
- [x] **COV-02**: Applicant sees any `SUBSTANTIATED` factor whose points still cannot be grounded as an explicit unresolved/unpriced item rather than a complete-looking result
- [x] **COV-03**: Applicant can import sibling relationship, status, age, and Canadian-residence proof into the vault, extract it as `pending`, and confirm/correct/reject each field before audit use
- [x] **COV-04**: Applicant receives `SUBSTANTIATED` for `additional.sibling` only when the claimed-scoped, confirmed evidence chain satisfies the corpus-grounded sibling rule; missing, stale, ambiguous, or cross-factor evidence remains `GAP`/`AT-RISK`

### Operational Hardening

- [x] **HARD-01**: Applicant receives a stable, PII-free, actionable refusal envelope when the corpus index is missing, empty, unreadable, corrupt, or content-drifted, using the frozen contract vocabulary plus a specific reason code
- [x] **HARD-02**: A grounding-prerequisite refusal returns a non-zero exit, recommends the existing index/doctor recovery command, and writes no audit, remediation, packet, or database artifact
- [x] **HARD-03**: The shipped synthetic profile example uses canonical dotted factor IDs, is pinned to the live factor grid, and produces applicable non-`N/A` verdicts through the real CLI path
- [x] **HARD-04**: Adversarial rotated, low-text, password-protected, and ambiguous-date fixtures remain quarantined and cannot green or contaminate another factor through the real import → extract → confirm → audit seam

### Grounded Remediation

- [x] **REM-01**: Applicant can generate a private remediation checklist from a selected completed audit run, with exactly one actionable item for each `GAP`, `AT-RISK`, or unresolved/unpriced factor
- [x] **REM-02**: Each remediation item identifies the factor, verdict/reason, score impact, existing grounded citation and verbatim rule span, and a deterministic action template keyed by factor and reason
- [x] **REM-03**: Remediation reuses already-grounded audit verdicts and citations without re-scoring, re-grounding, synthesizing volatile requirements, or creating a second advice/trust path
- [x] **REM-04**: The full remediation checklist and evidence pointers stay vault-only, while stdout exposes only a PII-light summary; every rendered artifact includes the substantiation-screening notice

### Redacted Professional Review Packet

- [x] **PKT-01**: Applicant can select audit/remediation findings and preview a dry-run redaction manifest before creating a lawyer/RCIC review packet
- [x] **PKT-02**: The packet is built from a closed allowlist projection whose schema cannot carry raw applicant values, absolute paths, or `ev_` evidence IDs unless a field is explicitly admitted by the packet contract
- [x] **PKT-03**: Raw, rendered, and OCR document content is excluded by default; any document inclusion requires an explicit per-document opt-in and remains staged inside the candidate vault
- [x] **PKT-04**: Packet creation records what was included, excluded, and redacted, writes only under the guarded vault packet subtree, refuses non-vault destinations/path escapes, and scans rendered bytes before write
- [x] **PKT-05**: The packet presents selected findings, score impact, and resolvable authoritative citations with prominent screening-not-legal-advice framing and no approval, eligibility, or outcome prediction

### Safety & Conformance

- [x] **SAFE-05**: Conformance proves every supported language benchmark is priced or explicitly unresolved, and no sibling or adversarial extraction state can produce a false-green verdict
- [x] **SAFE-06**: Privacy tests prove remediation and packet defaults leak no PII, raw document bytes, absolute paths, or `ev_` IDs; both new output subtrees remain unstageable and non-vault writes fail closed
- [x] **SAFE-07**: Retrieve-what-you-cite, deterministic-output, and static volatile-rule tests prove every requirement-bearing remediation/packet line derives from an existing grounded rule rather than synthesized advice
- [x] **SAFE-08**: The single release-gate command exercises coverage, refusal, remediation, packet, privacy, grounding, and screening-framing checks for the complete v4.1 flow

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Pre-ITA CRS scoring / profile optimization | The system substantiates an already-claimed score after ITA; it does not optimize a profile to obtain an ITA |
| Semantic entailment / NLI of applicant documents | Requires a model and adds a prohibited trust path; semantic duty/relationship ambiguity remains `AT-RISK` |
| Vector/embedding index or cloud document processing | Applicant PII must remain local and the existing keyword/citation trust path is frozen |
| Free-form generated fix or legal advice | Remediation must project grounded verdicts through deterministic templates; it cannot predict officer decisions |
| Automatic email, upload, or transmission to a lawyer/RCIC | The tool stages a packet inside the vault; the applicant controls any transfer |
| PDF packet generation | Markdown/JSON are sufficient for v4.1 and avoid a new renderer/dependency surface |
| Raw documents included by default | Conflicts with the privacy-first packet contract; inclusion is explicit and per-document only |
| Legacy arranged-employment, live DLI/PGWP, NOC-duty semantic, or MEC resolution | Separate policy/domain expansions retained as future requirements |
| Submitting forms to IRCC or interacting with IRCC accounts | The system guides and screens; the applicant acts |
| Legal advice or professional opinion | Output is substantiation screening and evidence organization, not a substitute for a licensed representative |
