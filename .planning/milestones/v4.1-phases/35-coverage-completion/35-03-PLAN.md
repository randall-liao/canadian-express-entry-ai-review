<objective>
Make the already-grounded sibling factor reachable by closing the gap on the EXTRACTION/evidence side
(COV-03): add the sibling evidence field vocabulary so an applicant can import sibling relationship,
status, age, and Canadian-residence proof into the vault, extract it as `pending`, and confirm/correct/
reject each field before audit use. The `additional.sibling` rule row already grounds (15 pts,
`crs-criteria.md#019`), but `decide_sibling` is structurally unreachable because the EXTRACT-01 field
vocabulary carries no sibling fields. This plan mirrors the Phase-30 30-05 shared-vocabulary pattern
exactly: a new `crawler/siblingfields.py` (names/enums only — the `testtypes.py` template), the four
sibling members added to the `FieldName` Literal, an `_FIELD_SPECS["sibling_proof"]` extraction spec,
`_DOC_TYPE_FACTOR["sibling_proof"] = "additional.sibling"`, a born-digital sibling fixture, and an
anti-drift pin. It does NOT touch the decider (plan 35-04 owns that) — it only makes the evidence
capturable, quarantined, and claimed-scoped.

Purpose: Satisfy COV-03 (per D — locked decisions: "Close sibling support on the extraction/evidence
side with pending-first, field-level confirmation and claimed-scoped linkage" and "Keep sibling evidence
fields in one shared vocabulary and pin producer/consumer agreement to prevent drift"). Preserve
vault-only PII storage and the `ev_` ↔ `citation_id` namespace separation.
Output: the shared vocab module, the extended `FieldName` + `_FIELD_SPECS` + `_DOC_TYPE_FACTOR`, a
fixture builder, an anti-drift vocab pin, and extraction/CLI regression coverage.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| imported sibling document → extraction | Untrusted document text crosses into structured fields; field NAME is validated at the `FieldName` pydantic boundary |
| extracted value → vault store | Every value is FORCED to `pending` (quarantine); only per-field confirmation makes it eligible |
| document → factor linkage | A value reaches a factor only if that factor is CLAIMED (parameterized SQL) — cross-factor contamination is structurally impossible |
| vault value → stdout/tracked tree | Sibling values are PII; they stay vault-only behind the publish-safe allow-list |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-35-03 | Tampering / Elevation | malicious/low-quality sibling document greens or pollutes evidence | mitigate | `add_extracted_value` forces `pending`; `is_audit_eligible` blocks pending/rejected/low_quality/ambiguous/stale; extraction is structural-only (no scoring); reused unchanged |
| T-35-04 | Elevation of Privilege | sibling evidence bleeds into age/nomination or a `--factor` injection targets an unclaimed factor | mitigate | `_DOC_TYPE_FACTOR["sibling_proof"]="additional.sibling"` + claimed-only `_resolve_factor` (parameterized SQL); test asserts UNLINKED when unclaimed and never `core.age`/`additional.nomination` |
