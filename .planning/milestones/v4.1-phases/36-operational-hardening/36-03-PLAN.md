<objective>
Prove — through the REAL `import_document -> extraction.extract_document -> confirm_value ->
audit_report.run_full_audit_report` seam — that adversarial rotated, low-text, password-protected, and
ambiguous-date documents remain quarantined and cannot green or contaminate another factor (HARD-04).
Today the real-seam tests use only clean fixtures, so a future relaxation of `is_audit_eligible` /
`classify_page_quality` / `_normalize_date` would go uncaught. This plan adds the durable regression net.

Purpose: lock the extraction quarantine + claimed-only linkage against regression. Output: one
skip-guarded real-seam test file; adversarial fixtures are generated at test time (no committed binaries,
`make_fixtures` left untouched). Production code changes ONLY if a probe reveals a real gate gap.
</objective>

Assertions (each imports → extracts → inspects the real values / runs the audit):

1. **Rotated scan quarantined.** Build a rotated language page carrying REAL extractable content —
   `mf.build_pdf([<the language_test page text with an ability score>], rotations=[90])` (do NOT use
   `mf.rotated_scan_pdf()`, whose placeholder text extracts zero values and would make this assertion
   vacuous if the rotation gate regressed). Import as `language_test` claiming `core.language.first`;
   extract; assert every produced value has `quality_flag == "low_quality"` and
   `vault.audit_eligible_values(v, "core.language.first")` is empty; run `run_full_audit_report` and assert
   the `core.language.first` card verdict != "SUBSTANTIATED".

2. **Low-text page quarantined.** Import `mf.language_test_multipage_pdf()` (page 2 is sparse, page 3
   empty) as `language_test`; extract; assert at least one value is `low_quality` and that no `low_quality`
   value is audit-eligible.

3. **Password-protected / unparseable quarantined.** Build a document the engine classifies
   `password_protected` by making it UNPARSEABLE to pypdfium2 — a truncated/garbage `.pdf`
   (e.g. `b"%PDF-1.4\ntruncated-garbage"`) reliably raises `pdfium.PdfiumError`, which `_pdf_pages` maps to
   a single `password_protected` page (an `/Encrypt` dict does NOT work — pdfium opens it cleanly; use a
   truncated PDF). Import as `passport` claiming `core.age`; extract; assert the produced page's quality
   dict has `password_protected == True` (→ `low_quality` via `_quality_flag`) and that
   `vault.audit_eligible_values(v, "core.age")` is empty (an unparseable page yields no text → no values,
   so this proves quarantine-by-absence on the PAGE quality flag, not on a value); `core.age` card !=
   "SUBSTANTIATED".

4. **Ambiguous DOB quarantined.** Import a passport page with `Date of Birth: 05/06/1994` (both ≤ 12) via
   `mf.build_pdf([...])` as `passport` claiming `core.age`; extract; assert the `date_of_birth` value has
   `quality_flag == "ambiguous"` and is not audit-eligible; `core.age` card != "SUBSTANTIATED".

5. **No cross-factor contamination.** For an adversarial `language_test` document claiming ONLY
   `core.language.first`, assert `vault.list_extracted_values(v)` places NO value on a different grid
   factor (e.g. `core.age`) — the claimed-only `_DOC_TYPE_FACTOR` linkage holds through the real seam; and
   assert every OTHER factor's `audit_eligible_values` is empty for this document.

6. **Confirm/correct cannot green an adversarial value.** Take one `low_quality` (or `ambiguous`) value
   and call `vault.confirm_value(..., decision="confirm")` (and separately `decision="correct"` with a
   plausible corrected value); assert the value is STILL not audit-eligible afterward — assert on
   `vault.is_audit_eligible(v, value_id) is False` and `vault.audit_eligible_values(v, factor)` stays empty.
   The quarantine holds STRUCTURALLY because `confirm_value` sets `confirmation_status` to
   `confirmed`/`corrected` but NEVER mutates `quality_flag`, and `is_audit_eligible` requires
   `quality_flag == 'ok'`; do NOT assert the status "re-enters pending" (it does not — key the assertion on
   eligibility, not on `confirmation_status`). If a future change let a `low_quality`/`ambiguous` value
   become audit-eligible via confirm/correct, that is a genuine fail-closed bug — fix it minimally in
   `vault.is_audit_eligible` (tightly coupled) and note it in the SUMMARY (not expected today).

Keep assertions value-anchored (quality flags, eligibility, verdicts) so the file is a durable contract.
