# Requirements: PR Review Agents — Canadian PR Application Guide

**Defined:** 2026-07-17
**Milestone:** v5.0 — Grounded Eligibility & Policy Edge-Case Screening
**Core Value:** Every answer about which documents are required and whether the user has them right is grounded in and cited from an authoritative source — the system never guesses on immigration requirements.

## v1 Requirements

Requirements for milestone v5.0. Each maps to exactly one roadmap phase (see Traceability). Phase numbering continues global sequence after Phase 39 — v5.0 begins at **Phase 40**.

**Milestone goal:** Extend the post-ITA system beyond CRS substantiation into deterministic, authoritative-source-grounded screening for Express Entry program eligibility (FSW/FST/CEC minimum entry criteria) and the policy edge cases v4.x deliberately left `AT-RISK` — legacy/physician arranged-employment, DLI/PGWP study evidence, and enhanced NOC work-duty review — plus cross-cutting policy effective-date/freshness/drift handling, while keeping semantic judgments human-confirmed and never presenting legal advice.

**Execution directive:** Planning and execution are autonomous. Agents make reasonable scope and implementation decisions, record rationale in milestone artifacts, and do not interrupt the operator with clarification questions.

**Standing constraints (apply to every requirement below):** PII stays vault-only and stdout PII-light; authoritative sources only (IRCC canada.ca guidance, Justice Laws IRPA/IRPR, IRCC PDIs, Ministerial Instructions); no legal advice and no eligibility/outcome prediction; no automated IRCC submission; fail-closed verdicts; no new/second trust path (reuse the frozen search → `--cite` → grounding-gate → JSON-envelope pipeline); prefer zero new dependencies (any addition requires strong justification + a supply-chain gate); no model/NLI/vector/cloud semantic auto-resolution; volatile facts (DLI/PGWP, program-eligibility thresholds, effective dates) are grounded in a pinned, refreshable **local snapshot**, never a live lookup at audit time.

### Minimum Entry Criteria — Program Eligibility (MEC)

- [x] **MEC-01**: Applicant can run a per-program (FSW / FST / CEC) minimum-entry-criteria screen that reports `MEETS` / `DOES-NOT-MEET` / `AT-RISK` on its own sidecar summary surface, framed as screening (no eligibility determination or outcome prediction), without altering the CRS substantiation total or the frozen public audit envelope
- [x] **MEC-02**: The FSW screen evaluates each grounded minimum requirement (skilled work experience, first-official-language CLB minimum, education) and the FSW 67-point selection grid from confirmed vault evidence, rolling up to `MEETS` only when every criterion passes; any failing, missing, or `AT-RISK` criterion yields `DOES-NOT-MEET`/`AT-RISK`
- [x] **MEC-03**: The FST and CEC screens each evaluate their own grounded minimum criteria (skilled-trades experience/language/qualification for FST; Canadian skilled-work duration and language for CEC) from confirmed vault evidence, fail-closed the same way
- [x] **MEC-04**: Every MEC criterion and threshold (work-hour/duration minimums, CLB minimums, grid points) is read from a grounded, cited rule row (FSW/FST/CEC PDI, IRPR, or Ministerial Instructions); no threshold is inlined in code or prose, and a missing, unconfirmed, stale, or `AT-RISK` criterion can never roll up to `MEETS`

### Legacy & Policy Edge-Case Arranged Employment (POLICY)

- [x] **POLICY-01**: An applicant with a pre-2025-03-25 in-window legacy arranged-employment claim receives a grounded `AT-RISK`/manual verdict selected by effective-dated rule windows — never `SUBSTANTIATED` or auto-green — while a post-repeal claim stays `AT-RISK`/0
- [x] **POLICY-02**: An applicant with a physician / public-policy special arranged-employment case receives a grounded `AT-RISK`/manual verdict citing the physician public-policy rule row, distinct from the general repeal path
- [x] **POLICY-03**: The resolver separates "a valid job offer for program-eligibility purposes" from "arranged-employment CRS additional points," so an offer can inform an MEC input without ever greening CRS points, and the shipped fail-closed `arranged_employment_guard` stays byte-for-byte frozen

### Canadian-Study DLI/PGWP Evidence (STUDY)

- [x] **STUDY-01**: A refreshable, authoritative DLI/PGWP-eligibility dataset is generated by the crawler into a pinned local corpus family carrying an as-of/`crawl_date` stamp and content hash, auto-indexed for grounded citation — with no live network lookup at audit time
- [x] **STUDY-02**: An applicant can import Canadian-study evidence (institution/DLI number, credential, program dates, status) into the vault, extract it as `pending`, and confirm/correct/reject each field before audit use
- [x] **STUDY-03**: The study screen substantiates Canadian-education study evidence only when confirmed evidence matches a grounded DLI/credential rule (exact DLI-number match + credential tier + the grounded R73(1) precondition); a confirmed credential level alone can never green it
- [x] **STUDY-04**: When the snapshot cannot prove a required temporal designation (e.g., DLI status during the study period) or is stale beyond the freshness bound, the study verdict stays `AT-RISK`/refusal rather than assuming current designation equals historical designation

### Enhanced NOC Work-Duty Review (NOC)

- [x] **NOC-01**: An applicant can view a structured, cited worksheet of the grounded NOC 2021 lead statement, main duties, and employment requirements for their claimed NOC, resolved from the corpus with resolvable citations
- [x] **NOC-02**: An applicant confirms, per duty, whether their claimed work performed that duty, and each confirmation is captured as a vault field under the extraction-quarantine (confirm/correct/reject, staleness-keyed) — with no automated semantic entailment or keyword-overlap match scoring
- [x] **NOC-03**: The NOC duty-review verdict stays `AT-RISK` until the human confirms the required duty match; it can never reach `SUBSTANTIATED` by automated matching, and unconfirmed, partial, or stale confirmations remain `AT-RISK`/`GAP`

### Safety, Freshness & Conformance (SAFE)

- [x] **SAFE-09**: A shared freshness/effective-date guard ensures no grounded rule row or local snapshot that is outside its effective window or beyond its staleness bound can contribute to a green verdict; the staleness bound is a grounded/config value, not an inlined literal
- [x] **SAFE-10**: The corpus/index/snapshot preflight refuses cleanly — stable PII-free reason code, non-zero exit, and zero audit/screen/database artifacts written — when a required snapshot or index is missing, empty, unreadable, corrupt, stale, or content-drifted
- [x] **SAFE-11**: The no-inlined-volatile-rules static gate and the retrieve-what-you-cite grounding check extend to cover every new v5.0 rule family (MEC, POLICY, STUDY, and the DLI snapshot), so each new threshold or date derives from a grounded, cited corpus span
- [x] **SAFE-12**: A single v5.0 release-gate command exercises every new screen (MEC, POLICY, STUDY, NOC), the "stale/superseded/out-of-window/unconfirmed never greens" invariant, snapshot freshness/provenance, PII containment (no PII, `ev_` IDs, or absolute paths on stdout/envelope/snapshot), the zero-new-dependency check, and screening-not-legal-advice framing for the complete v5.0 flow

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Live/remote DLI, PGWP, or program-eligibility lookup at audit time | Volatile external facts must be grounded in a pinned, dated, reproducible local snapshot; a live lookup breaks the frozen local-corpus trust path and can green a result from unpinned data |
| Automated semantic NOC duty matching (entailment / NLI / keyword-overlap scoring) | Requires a model and adds a prohibited trust path; duty fit stays a structured, cited, human-confirmed worksheet capped at `AT-RISK` |
| Vector/embedding index or cloud document processing | Applicant PII must remain local and the existing keyword/citation trust path is frozen |
| Pre-ITA CRS scoring / profile optimization | The system screens after an ITA is received; it does not optimize a profile to obtain an ITA |
| Program recommendation or "you are eligible / will be approved" statements | Output is grounded screening and evidence organization; the officer decides — the tool never predicts an outcome |
| Legal advice or professional opinion | Output is substantiation + eligibility screening, not a substitute for a licensed immigration consultant/lawyer |
| Admissibility, H&C, or substituted-evaluation determinations | Officer-only discretionary judgments outside a grounded deterministic screen |
| Recipient-specific export presets; encrypted packet bundles | Retained as future requirements (LATER-06, LATER-07) pending a separate key-management threat model |
| Submitting forms to IRCC or interacting with IRCC accounts | The system guides and screens; the applicant acts |
| New runtime dependencies without strong justification | Threatens the dependency-light, PII-safe, CLI-agnostic constraints; any addition requires a supply-chain gate |
