<objective>
Ship the SAFE-10 snapshot preflight MECHANISM: a read-only, side-effect-free `probe_snapshot` that
classifies a required corpus family into a CLOSED reason-code vocabulary (adding `snapshot_stale` and
`snapshot_missing` on top of the reused missing/empty/unreadable/corrupt/drifted base), plus a
`cli._require_readable_snapshot` wrapper that turns any non-ok health into the frozen
`invalid_input`/exit-2 refusal with a PII-free `reason=<code>` token — refusing BEFORE any `open_vault`
so a refusal writes ZERO artifacts. A healthy snapshot returns None (permits downstream — SC4).

This is a strict additive mirror of the shipped `probe_index` / `IndexHealth` / `INDEX_*` /
`_require_readable_index` preflight. The frozen `probe_index` signature and its tests stay byte-stable
(`probe_snapshot` reuses `probe_index` internally). Phase 40 proves the mechanism against SYNTHETIC
fixture snapshot families in a tempdir — it does NOT depend on the real corpus or the not-yet-existent
`corpus/dli/` family (that is Phase 41). No user-facing verb is added: the shipped verbs that will call
`_require_readable_snapshot` are Phase 44/45 (Assumption A5); Phase 40 proves the wrapper via a
fixture-driven refusal test.

Purpose: Give STUDY/MEC-CEC a clean fail-closed refusal on an absent / stale / drifted DLI family
before any write, closing the milestone's missing/stale/drifted-snapshot clean-refusal risk (Pitfall 8).
Output: `SnapshotHealth` + `probe_snapshot` + `SNAPSHOT_*` in `index_health.py`;
`_require_readable_snapshot` in `cli.py`; new `test_snapshot_health.py` + `test_snapshot_refusal.py`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator `--db` / snapshot family input → read-only DB probe | Untrusted path + family string cross into a SQL query and a filesystem open; must be read-only and injection-safe |
| snapshot content (chunk text + crawl_date) → freshness/integrity verdict | Tampered / drifted / stale snapshot content must be classified fail-closed, never silently accepted |
| refusal message → stdout / JSON envelope | Only PII-free corpus tokens may cross to stdout; no applicant value, `ev_` id, or vault path |
| refusal decision → filesystem | A refusal must happen BEFORE any vault open/write so zero artifacts are produced |
