## Summary

Phase 41 delivers the milestone's single genuinely-new corpus artifact: a pinned, dated,
content-hashed `corpus/dli/` family generated out-of-band from the authoritative IRCC DLI/PGWP
dataset, auto-indexed by the existing FTS5 builder with zero indexer changes, plus one grounded
rule row that resolves a verbatim span from the family, an offline fixture snapshot, and a fail-closed
freshness/provenance contract — with **no network access at audit time**.

The authoritative machine-readable source is **verified live**: the canada.ca "Designated learning
institutions list" page loads its full data via a WET-BOEW `wb-tables` AJAX source at
`https://www.canada.ca/content/dam/ircc/documents/json/dli/dli-full-list.json` (HTTP 200,
`application/json`, `Last-Modified: 2026-07-16`, robots-allowed, byte-identical across two fetches).
The payload is `{"data":[ ... ]}` with **1,454 campus-level rows / 1,136 distinct DLI numbers** and nine
flat string fields per row (`Province, Institution, DLI #, City, Campus, Grad Program, PGWP, HTML,
Public/Private`). Critically, **PGWP is tri-state** (`Yes` / `No` / `Details`), the same DLI number can
carry **multiple institution names** (18 cases) and **conflicting PGWP values across campuses** (2 cases),
two DLI numbers carry **trailing whitespace**, and **the source exposes only *current* status — no
historical designation window, no PGWP-eligibility date, and no normative refresh cadence / max-age**.

The build stays zero-dependency: the refresh generator uses **stdlib `urllib.request` + `json` +
`hashlib`** (no `crawl4ai`, no `httpx`) because the source is a single structured JSON download, not a
browser-rendered page. Every integration seam is already frozen and proven: `searchindex.build_index`
auto-enumerates any `corpus/dli/*.md` with front-matter via `dupaudit.live_docs`; `crs_rules.load_registry`
auto-loads any new `data/crs_rules/*.yaml`; `index_health.probe_snapshot(db, "dli", …)` already classifies a
`relpath LIKE 'dli/%'` family into the closed `SNAPSHOT_*` vocab; and Phase 40 shipped the freshness
MECHANISM — `crs_audit.within_freshness` / `row_in_effect`, additive siblings that read a max-age window
from a **caller-supplied** `Registry` via `_window_days` and fail closed when no window is grounded — plus
the STRINGS-only field-name contract `_FRESHNESS_FIELD['dli_snapshot'] = 'snapshot_max_age'`. Phase 40 did
**NOT** ship a `safe.dli_snapshot.max_age` rule id, any `data/crs_rules/*.yaml` bound row, or a concrete
`window_days` value: SAFE-09 was proven with a SYNTHETIC in-test grounded `validity_window` fixture (its
`window_days=180` is illustrative only, never a shipped/pinned value — `git status` on the shipped registry is
clean). `[VERIFIED: crs_audit.py:39-47,173-189; test_freshness_staleness.py:64-81; no study_dli.yaml or snapshot_max_age row in crawler/data/crs_rules/]`

**Primary recommendation:** Add ONE new stdlib module `crawler/dli_snapshot.py` (fetch → strict closed-schema
validate → normalize → per-**DLI-number** canonical markdown docs with `crawl_date` = upstream
`Last-Modified` and a body-only `content_sha256`, plus a non-indexed `corpus/dli/manifest.json` family
provenance record), a new **top-level** `refresh-dli` argparse verb (registered on the `corpus-crawler` prog
directly beside the existing top-level `index`/`crawl` verbs — there is **no** `corpus` parent subcommand to
nest under), emitting the frozen five-key envelope, a committed fixture JSON + generated fixture family under
`crawler/tests/fixtures/dli/`, and **one** grounded `study_dli.yaml` row — `study.dli.designation` — that
cites a verbatim current-status span from a per-DLI doc (that doc is a faithful deterministic representation
of the authoritative IRCC payload, so the citation grounds *current-status* facts only). Phase 41's freshness
responsibility is to make staleness **measurable** — stamp the authoritative upstream `Last-Modified` as-of
and a content hash on every doc; it ships **NO** `safe.dli_snapshot.max_age` row and **no** concrete max-age
value. The concrete max-age is an operational config decision owned by **Phase 44 (STUDY-04)** under SAFE-09's
explicit "grounded/**config** value" allowance — a required explicit value with no fabricated normative
default whose absence must fail closed at the consumer. Never self-ground operational policy from a
project-authored doc, and never fabricate an IRCC max-age citation.

### What the source CAN and CANNOT prove (drives the Phase 44 contract)

- **CAN prove (as of the crawl date):** current DLI designation (presence in the list), current
  institution name(s), campuses/cities, public/private sector, graduate-program flag, and **current**
  PGWP eligibility as one of `Yes`/`No`/`Details`. `[VERIFIED]`
- **CANNOT prove:** (a) **historical designation** — there is NO effective-from/to, no "designated on"
  date, no temporal window in the payload; (b) **PGWP eligibility for a specific program** — `Details`
  (356 rows) explicitly defers to a per-institution sub-page and is conditional on program/curriculum
  licensing; (c) any **normative refresh cadence / max-age** — the page and JSON publish no "updated every
  N days" statement. `[VERIFIED: absence confirmed via grep for as-of/effective/moratorium/updated language]`

> **Fail-closed metadata contract Phase 44 must consume:** treat the snapshot as a **current-status**
> proof only. `PGWP == "Yes"` ≠ credential-points eligibility; `PGWP == "Details"` ⇒ `AT-RISK`/manual
> (never eligible); a DLI present today does NOT prove designation *during the applicant's study period*
> → `AT-RISK`/refusal, never "current == historical." Match strictly on the **normalized DLI number**,
> never the institution name.

### Data-quality landmines (verified — every one needs deterministic handling)

| Landmine | Evidence | Required handling |
|----------|----------|-------------------|
| Trailing whitespace in `DLI #` | `'O110120953397 '`, `'O2119619009722 '` | `.strip()` before use in identity/filename/citation |
| Same DLI # → multiple institution names (18) | `O19305471522` → University of Waterloo + Conrad Grebel + St. Jerome's + St. Paul's; `O112937696097` → `'Eastern College'` vs `'Eastern College '` | Canonical doc **per DLI number**, listing the union of name variants; strip name whitespace |
| Same DLI # → conflicting PGWP across campuses (2) | `O153601941355`, `O246875965662` → both `Details` and `No` | Preserve **per-campus** PGWP verbatim in the doc (a campus table); never collapse to one DLI-level PGWP |
| Non-ASCII institution names (332) | `’` U+2019, `é`/`è`/`à` | Apply **Unicode NFC** normalization for byte-reproducible hashing; keep quotes/text consistent so the grounding gate (no Unicode folding) matches |
| `Details` PGWP defers off-JSON (356) | `HTML` anchor to `…/cla.html`, `…/quebec.html`, `…/<institution>.html` | Record `PGWP: Details` verbatim; do NOT follow/crawl sub-pages (out of scope); mark as conditional |
| Upstream row order / campus fan-out | up to 16 campuses per DLI | Deterministic sort (DLI# asc, then City/Campus) so output is stable |

### Pattern 1: Zero-dep out-of-band fetch with injectable payload (testability)

**What:** `dli_snapshot.py` exposes a pure `normalize(payload_dict, *, as_of) -> list[InstitutionDoc]`
and a thin `fetch() -> (payload_dict, last_modified)` seam bound to `_DLI_URL`, so tests exercise `normalize`/`write`
against a fixture payload with **no network**. Mirrors how `pipeline.classify_pages` was factored out of
`deepcrawl` to make offline parity tests possible. `[VERIFIED: crawler/pipeline.py docstring]`

**When to use:** always — the network `fetch` is a 5-line seam; all logic lives in pure functions.

```python
# Source pattern: crawler/deepcrawl.py front-matter emit + crawler/pipeline.py pure-classifier split
def fetch(url: str, *, timeout: int = 60) -> tuple[dict, str | None]:
    # stdlib only; polite UA; explicit timeout; no redirects off canada.ca
    req = urllib.request.Request(url, headers={"User-Agent": _UA, "Accept": "application/json"})
    with urllib.request.urlopen(req, timeout=timeout) as r:   # nosec — fixed authoritative host
        last_modified = r.headers.get("Last-Modified")
        payload = json.loads(r.read().decode("utf-8"))
    return payload, last_modified

def normalize(payload: dict, *, as_of: str) -> list["DliDoc"]:
    rows = payload.get("data") or []
    by_dli: dict[str, list[dict]] = {}
    for raw in rows:
        dli = _nfc(str(raw.get("DLI #", ""))).strip()       # strip trailing space
        if not _DLI_RE.fullmatch(dli):                       # fail-closed: skip malformed identity
            continue
        by_dli.setdefault(dli, []).append(raw)
    docs = [_build_doc(dli, sorted(campuses, key=_campus_key), as_of=as_of)
            for dli, campuses in sorted(by_dli.items())]     # deterministic order
    return docs
```

### Pattern 2: Per-DLI canonical markdown doc (front-matter + verbatim-citable body)

**What:** one `corpus/dli/<DLI#>.md` per DLI number, generated as a **faithful deterministic representation
of the authoritative IRCC payload**. Front-matter carries provenance; the body carries a **stable, quotable
designation line**, an explicit **current-status-only limitation** line, plus a **per-campus PGWP table**
(preserves the 2 conflicting-PGWP cases). File starts with `---` so `dupaudit.live_docs` enumerates it.
`[VERIFIED: dupaudit.live_docs:157-166]`

> quote from it (e.g. `DLI number: O19332746152`) grounds a **current-status** fact, and only that.

### Pattern 3: Atomic full-family replace (handles deletions + idempotency)

**What:** `write(docs, out_dir)` regenerates the WHOLE requested family root: resolve `out_dir`, contain
every validated DLI filename beneath that root, stage into a sibling temporary directory, validate, then
swap with rollback. This honors temp/golden roots in tests while the CLI passes only fixed
`Path("corpus/dli")`. It handles institutions REMOVED upstream (stale files cannot linger) and preserves
the previous family on failure. `[VERIFIED: crawler/paths.py resolve_within is the generic containment primitive]`

**Why not incremental diff:** `build_index` already does a full DROP+rebuild for idempotency; matching that
with a full-family regenerate keeps both layers deterministic and avoids stale-file bugs. `[VERIFIED: searchindex.build_index:303-330]`

### Pattern 4: Measurable freshness provenance (crawl_date + content hash + non-indexed manifest)

**What:** Phase 41 makes staleness **measurable** — it does NOT set a max-age bound. Every per-DLI doc
stamps `crawl_date` (= upstream `Last-Modified`) and a body `content_sha256`; a **non-indexed**
`corpus/dli/manifest.json` records the source URL, the as-of/`Last-Modified`, the family-level content hash,
a current-status-only note, and the generator id. `manifest.json` is project-authored data-lineage metadata:
it carries no `.md` extension, so `dupaudit.live_docs` never enumerates it into the index, and **no grounded
rule row ever cites it**. `[VERIFIED: dupaudit.live_docs drops files without front-matter / non-.md; searchindex only chunks live_docs]`

**Why not a self-authored `00-about` grounded row:** a generated project-authored doc is NOT an authoritative
immigration source. Citing an operational "treated as stale after N days" span from such a doc as a grounded
`safe.dli_snapshot.max_age` row would fabricate an authoritative-source grounding path that does not exist —
the exact trust-boundary error this phase must avoid. The **operational max-age** is instead a Phase 44
(STUDY-04) config value under SAFE-09's "grounded/**config** value" allowance: a required explicit value,
no fabricated normative default, whose absence fails closed at the consumer (`probe_snapshot` applies the
staleness gate only when `max_age_days` is supplied, so the Phase-44 caller must refuse/`AT-RISK` when the
config is missing rather than pass `None`). `[VERIFIED: index_health.probe_snapshot:224-246,286 — max_age_days caller-supplied, staleness skipped when None]`

### Anti-Patterns to Avoid

- **Self-grounding operational policy from a project-authored doc.** A generated `00-about`/manifest doc is
  NOT an authoritative IRCC source; never cite it as a grounded rule row or treat it as satisfying the
  authoritative-source grounding trust path. The one shipped grounded row cites only the IRCC-derived per-DLI
  doc for a current-status fact. `[CITED: STATE.md frozen invariant "authoritative sources only"]`
- **Shipping a `safe.dli_snapshot.max_age` row in Phase 41.** The concrete max-age is Phase-44 operational
  config (STUDY-04); ROADMAP SC1–SC4 for Phase 41 do not require it. `[CITED: ROADMAP.md:176-181, REQUIREMENTS.md:34-35,45]`
- **Following the `Details` sub-page links.** 356 rows link to per-institution PGWP sub-pages; crawling
  them is out of scope and would re-introduce a browser/HTML path. Record `PGWP: Details` verbatim and stop.
- **Collapsing per-campus PGWP to one DLI-level flag.** Loses the 2 conflicting cases → misrepresentation.
- **Institution-name file naming / name matching.** 18 shared-DLI and trailing-space collisions → unstable.
- **Wall-clock `crawl_date` inside the hashed body.** Breaks byte-reproducibility (SC3).
- **Asserting historical designation or program-level PGWP eligibility.** The snapshot proves current status
  only; a doc/row that implies designation *during* a study period or that `PGWP: Yes` = credential-points
  eligibility is a false-green feeder for Phase 44.
- **Reading the vault in the generator.** Pitfall 6 — the snapshot is public-shaped; a vault read poisons a
  public file with PII. The generator reads ONLY the IRCC dataset. `[CITED: PITFALLS.md:113-119]`
- **A second DLI datastore or a decider that reads the raw `.json`.** One FTS5 index is the only store;
  deciders consume gated grounded rows, never the raw JSON. `[CITED: PITFALLS.md:132-141]`
- **Inlining any volatile number (e.g. a max-age) in Python/prose.** `no_inlined_volatile_rules` scans
  deciders/prose; volatile windows live only in grounded YAML machine_check payloads or explicit config —
  never a Python literal. (Phase 41 ships no such number.) `[VERIFIED: crs_rules.no_inlined_volatile_rules]`

## Common Pitfalls

### Pitfall 1: Stale snapshot silently greens a study screen (milestone dominant risk)
**What goes wrong:** the family indexes and grounds fine, so a too-old snapshot passes unnoticed until the
data ages. `[CITED: PITFALLS.md:148-160]`
**How to avoid (Phase 41's part):** make staleness **measurable** — stamp `crawl_date` (= upstream
`Last-Modified`) + a body `content_sha256` on every doc and record the family provenance in the non-indexed
`manifest.json`. The **max-age bound** that turns measurability into refusal is SAFE-owned and lives in
**Phase 44 config** (STUDY-04): the Phase-44 caller passes it as `probe_snapshot(..., max_age_days=<config>)`
/ `within_freshness(...)` and MUST fail closed (refuse/`AT-RISK`) when the config is absent — never pass
`None` and proceed. Do NOT ship a `safe.dli_snapshot.max_age` row this phase, and never self-ground the bound
from a project-authored doc. **Warning sign:** a `corpus/dli/*.md` with no `crawl_date`; a green study
verdict with no as-of surfaced; a max-age literal appearing in Phase-41 code or a grounded row.

### Pitfall 2: Non-reproducible refresh (SC3 fail)
**What goes wrong:** same upstream payload → different output bytes/hash (wall-clock in the body,
dict-order nondeterminism, unsorted campuses).
**How to avoid:** derive `crawl_date` from `Last-Modified`; NFC-normalize; sort by DLI# then City/Campus;
hash the body only. **Warning sign:** two runs over the fixture JSON produce different `content_sha256`.

### Pitfall 3: Institution ≠ program ≠ current-vs-historical conflation (feeds Phase 44)
**What goes wrong:** treating `PGWP: Yes`/current designation as sufficient, or implying designation *during*
a prior study period. `[CITED: PITFALLS.md:72-87]`
**How to avoid (Phase 41's part):** emit the normalized DLI number for exact-match; record `PGWP` verbatim
including `Details`; state the current-status-only limitation explicitly in each doc's front-matter
(`status_scope: current-only`) AND body, and in the manifest — and assert it in a test. **Warning sign:** a
doc that asserts eligibility rather than status; a `Details` row rendered as eligible; a body implying
historical designation.

### Pitfall 4: PII leak via the generator
**What goes wrong:** the generator reads the vault to "personalize," poisoning a public file; or an absolute
path leaks into a doc/envelope. `[CITED: PITFALLS.md:110-122]`
**How to avoid:** generator reads ONLY the IRCC dataset; write via the `crawler/paths.py` resolve-then-contain
gate; run `scripts/check_publish_safe.py` over the tracked tree including any committed fixture family.
**Warning sign:** a candidate id/name/`ev_` id/home path in `corpus/dli/*.md` or the `--json` envelope.

### Pitfall 5: Grounding-gate Unicode mismatch
**What goes wrong:** the cited quote uses `'` (U+0027) but the doc body has `’` (U+2019) → the gate (no
Unicode folding, only whitespace/case) fails to ground. `[VERIFIED: grounding._norm]`
**How to avoid:** NFC-normalize doc bodies AND copy the rule-row `quote` verbatim from the generated body;
prefer citing an ASCII-only line (the `DLI number: O…` line) for the shipped grounded row.

### Pitfall 6: Committed fixture drifts from the generator
**What goes wrong:** the shipped `study_dli.yaml` cites `dli/<file>.md#000` with a quote, but the fixture
family is hand-edited and no longer matches → deterministic grounding test breaks (or, worse, the real
corpus is git-ignored so nothing catches it in CI).
**How to avoid:** generate the fixture family by running the generator over the committed `dli-sample.json`;
pin it golden; a test regenerates and asserts byte-identity + grounding. **Warning sign:** editing a fixture
`corpus/dli/*.md` by hand.

### Pitfall 7: Self-grounding operational policy / fabricating an authoritative citation
**What goes wrong:** to satisfy SAFE-09 mechanically, a plan generates a `00-about` doc that says "treated as
stale after N days" and cites it as a grounded `safe.dli_snapshot.max_age` row — fabricating an
authoritative-source grounding path from project-authored prose. `[CITED: STATE.md "authoritative sources only"]`
**How to avoid:** ground only IRCC-derived per-DLI docs (current-status facts). The operational max-age is a
Phase-44 config value, not a grounded corpus span; no max-age number appears in Phase-41 code or rows, so
`no_inlined_volatile_rules` stays clean without inventing a citation. **Warning sign:** a rule row whose
`quote` resolves to a self-authored provenance doc; any `treated as stale after` text presented as guidance.

### `refresh-dli` CLI handler (top-level verb; fixed endpoint/output + frozen envelope)

`refresh-dli` is a **new top-level subparser** registered directly on the main `subparsers`
(`dest="command"`) in `build_parser()` — beside `p_index`/`p_crawl`, NOT under a (non-existent) `corpus`
parent — with `p_refresh.set_defaults(func=_cmd_refresh_dli)`. The `metavar` string on `add_subparsers`
(cli.py:1521) is extended to include `refresh-dli`. The command exposes no arbitrary URL, input-file, or
output-path option: it fetches the fixed IRCC endpoint and writes only `corpus/dli/`. Tests patch
`dli_snapshot.fetch` or call pure generator functions with temp directories.
`[VERIFIED: crawler/cli.py:1508-1572 top-level subparser pattern; prog="corpus-crawler"]`

```python
# Source pattern: crawler/cli.py::_cmd_index (thin dispatcher: validate → lazy import → contract envelope)
def _cmd_refresh_dli(args) -> int:
    from crawler import dli_snapshot
    try:
        payload, last_modified = dli_snapshot.fetch()                  # fixed IRCC URL; network ONLY here
    except (urllib.error.URLError, TimeoutError, OSError) as exc:
        msg = f"could not fetch DLI dataset: {exc}"
        print(msg, file=sys.stderr)
        if args.json:
            contract.emit(contract.envelope("refresh-dli",
                          error=(contract.INVALID_INPUT, msg)))
        return contract.EXIT_INVALID_INPUT
    try:
        as_of = dli_snapshot.as_of_from(last_modified)                 # deterministic crawl_date; fail-closed if absent
        docs = dli_snapshot.normalize(payload, as_of=as_of)            # strict closed-schema validate inside
    except dli_snapshot.SchemaError as exc:                           # unexpected/missing field, bad as-of, empty data
        msg = f"DLI dataset failed schema validation: {exc}"
        print(msg, file=sys.stderr)
        if args.json:
            contract.emit(contract.envelope("refresh-dli",
                          error=(contract.INVALID_INPUT, msg)))
        return contract.EXIT_INVALID_INPUT
    result = dli_snapshot.write(                                      # fixed family; atomic replace + manifest
        docs, out_dir=Path("corpus/dli")
    )
    if args.json:
        contract.emit(contract.envelope("refresh-dli", result={
            "out": "corpus/dli", "institutions": result["docs"],
            "campuses": result["rows"], "as_of": as_of,
            "family_sha256": result["family_sha256"],                  # PII-free provenance only
        }))
    else:
        print(f"dli: {result['docs']} institutions / {result['rows']} campuses "
              f"as_of={as_of} -> corpus/dli", file=sys.stderr)          # human summary → stderr
    return 0
```
